# aligner-benchmarking-f1-throughput

## Summary

Benchmark protocol for comparing read classifiers/aligners (SPUMONI vs minimap2) on host-depletion tasks, scoring per-read decisions with F1 and reporting throughput (kbp/s) and index size across one-genome vs multi-genome indexes.

## When to use

Use when comparing accuracy and speed of read classification tools against large, repetitive references (e.g. human pan-genomes) in nanopore depletion or targeted-sequencing scenarios.

## When NOT to use

- When the task is real-time signal-level read-until control — SPUMONI operates on base-called sequences and cannot directly interact with the Read Until API
- When the target and non-target sequences share substantial similarity (e.g. conserved genes between species), since the null-index hypothesis testing may be insufficient
- When the reference is small and non-repetitive, where the compressed-index advantages (index size, memory) being benchmarked do not apply

## Inputs

- Real nanopore read set (FASTQ/FASTA) from SRA accession SRX6602475
- Simulated human nanopore reads from CHM13 generated by PBSIM2 at 90% base-call accuracy
- Reference multi-FASTA files: one-genome (CHM13 only) and three-genome pan-genome (CHM13 + Ashkenazi Ash1 + GRCh38)

## Outputs

- Per-read classification/alignment decisions for SPUMONI and minimap2 under each index configuration
- Aggregated comparison table (table4_spumoni_vs_minimap2.csv) with F1 score, throughput (kbp/s), and index size (GB) per tool per index configuration

## How to apply

Obtain a real nanopore read set (e.g. SRA SRX6602475) and generate simulated target reads with PBSIM2 (e.g. CHM13 at 90% base-call accuracy). Build indexes for each configuration — here SPUMONI indexes with 'spumoni build -r <ref.fa> -M -P -m -o <prefix>' computing both matching-statistics and pseudo-matching-length indexes over a one-genome (CHM13) and a three-genome (CHM13 + Ashkenazi + GRCh38 multi-FASTA) reference. Run classification with 'spumoni run -r <index> -p reads.fa -P -c' in PML mode and align the same reads with minimap2 as baseline. Aggregate per-read decisions into F1 score, throughput in kbp/s, and index size (GB), then write a comparison CSV and check against reported figures (F1 96.97 vs 95.17 one-genome; 97.08 vs 99.17 three-genome; throughput 27.0 vs 13.5 kbp/s three-genome; index sizes ~18 vs 21 GB).

## Related tools

- **SPUMONI** (Read classifier under test; builds matching-statistics and PML indexes and classifies reads with PML mode) — github.com/oma219/spumoni
- **minimap2** (Alignment baseline against which SPUMONI's F1 and throughput are compared)
- **PBSIM2** (Generates simulated nanopore reads (90% base-call accuracy) from CHM13 to mix with real microbiome reads) — github.com/yukiteruono/pbsim2

## Examples

```
spumoni build -r chm13_ash1_grch38.fa -M -P -m -o human3idx && spumoni run -r human3idx -p reads.fa -P -c
```

## Evaluation signals

- Reproduced one-genome F1 values: SPUMONI 96.97 vs minimap2 95.17
- Reproduced three-genome values: SPUMONI F1 97.08 vs minimap2 99.17, and throughput 27.0 vs 13.5 kbp/s
- Index sizes land near reported values (~18 GB SPUMONI vs ~21 GB minimap2 for three human genomes)
- SPUMONI runs in PML mode ('spumoni run -r <index> -p reads.fa -P -c') producing per-read classification reports comparable to minimap2 alignments
- Throughput metric expressed in kbp/s is computed consistently for both tools over the same read set

## Limitations

- The throughput advantage of SPUMONI over minimap2 is limited for human reads; authors expect it to improve only as the number of human genomes in the reference increases
- A single KS-stat threshold is used for all experiments; the optimal threshold depends on read accuracy and the reference, and no per-experiment thresholding method is provided
- The null index (reverse of positive-index sequences) may fail when there is substantial sequence similarity between depletion-target and non-target reads
- SPUMONI requires a separate base caller upstream and cannot directly interact with the Read Until API
