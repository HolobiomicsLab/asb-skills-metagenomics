# barcoded-paired-end-fastq-simulation

## Summary

Simulate realistic 10x Chromium Linked-Read data with LRTK-SIM: build diploid hg38 templates carrying NA12878 SNVs, shear haplotypes into exponentially distributed fragments, assign them to barcoded droplets, and emit gzipped paired-end FASTQ compatible with 10x pipelines.

## When to use

Use when generating synthetic 10x Chromium Linked-Read FASTQ data for testing de novo assembly (Supernova2) or variant pipelines (Long Ranger), or when exploring parameter combinations such as CF, CR, Mu_F, and N_FP before real library preparation.

## When NOT to use

- You need structural variants (indels, SVs) in the simulated genome — the current gen_fasta.py version supports only SNVs
- You require haploid simulation but leave Hap=2 and both haploid FASTA paths set; instead remove Path_Fastahap2 and set Hap=1
- Real (not simulated) 10x data are already available for the analysis — use the real libraries rather than synthesizing parameter combinations

## Inputs

- hg38 reference genome sequence (FASTA)
- GIAB NA12878 SNV variant calls (VCF, compressed or uncompressed)
- LRTK-SIM configuration file(s) (e.g., config1.txt, config2.txt) with line-positioned parameters CF, CR, N_FP, Mu_F, SR, error rate, Mu_IS, Std_IS, Hap
- Optional: species-abundance flat file (sequence name + abundance summing to 1) for metagenomic simulation

## Outputs

- Two haploid reference FASTAs generated by gen_fasta.py
- Per-library output folders (lib_config1/, lib_config2/, ...) under the config path
- Paired gzipped FASTQ files per library: X_S1_L001_R1_001.fastq.gz (forward) and X_S1_L001_R2_001.fastq.gz (reverse), barcoded 10x-style reads

## How to apply

First run gen_fasta.py to insert GIAB NA12878 SNVs from a VCF into the hg38 reference, producing two haploid FASTAs (only SNVs are supported; note the 2:1 het:hom ratio used in the paper). Fill a config file with line-positioned parameters: the two haploid FASTA paths (lines 2/3), processors (line 5), physical fragment coverage CF (line 7), per-fragment read coverage CR (line 9), fragments per droplet N_FP (line 11), mean fragment length Mu_F in Kb (line 13), short-read length SR (line 15), sequencing error rate (line 21), insert-size mean Mu_IS and Std_IS (lines 27/29), and Hap=2 for diploid simulation (line 33). Run 'python LRTK-SIM.py <config folder>' — the simulator uses python3, numpy, and multiprocessing to simulate multiple libraries simultaneously. Fragment lengths are drawn from an exponential distribution with mean mu_FL and fragments are assigned to barcoded pseudo-partitions via a Poisson model on N_FP. For the paper's assembly-parameter study, keep CF in the optimal 332x–823x window (never >1,000x) and length-weighted fragment length near 50–150 kb. Output is one lib_<config> folder per library holding gzipped forward/reverse FASTQ pairs.

## Examples

```
python gen_fasta.py -v sample.vcf -r ref.fasta -p newref -o ./work; python LRTK-SIM.py ./diploid_config
```

## Evaluation signals

- Each library folder (lib_configX) contains both configX_S1_L001_R1_001.fastq.gz and configX_S1_L001_R2_001.fastq.gz
- The simulated FASTQ files are accepted without errors by 10x official pipelines Long Ranger and Supernova
- Haploidy setting matches input: two haploid FASTAs with Hap=2, or a single FASTA with Path_Fastahap2 removed and Hap=1
- Simulated coverage statistics match the configured CF (physical fragment coverage) and CR (read coverage per fragment) values
- For assembly-parameter studies, resulting CF falls in the 332x–823x optimal window and stays below 1,000x for a given C

## Limitations

- gen_fasta.py supports only SNVs in this version; indels and structural variants cannot be inserted into the simulated diploid template
- Simulated parameter ranges are calibrated for human diploid assembly (Supernova2); parameter choices such as CF > 1,000x are known to degrade assembly quality
- For metagenomic simulation, species abundances must be provided in a two-column flat file with names identical to reference sequence names and summing to 1
