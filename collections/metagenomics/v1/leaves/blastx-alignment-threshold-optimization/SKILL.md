# blastx-alignment-threshold-optimization

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Empirically sweeps Diamond blastx identity-coverage-evalue threshold combinations on simulated Illumina reads from a mock community to identify the filter settings that maximize the mapping rate of fungal reads to the FunOMIC-P functional protein database.

## When to use

Use when calibrating translated-DNA alignment cutoffs (identity %, read coverage %, e-value) for a functional protein database against simulated or mock-community metagenomic reads.

## When NOT to use

- Input is already an annotated functional profile (e.g. a KEGG/knockout count table) rather than raw or simulated metagenomic reads
- The target database is nucleotide-based (use blastn/bowtie2-style filters, not translated blastx coverage/identity sweeps)
- The goal is taxonomic profiling of marker genes with FunOMIC-T, whose mapping uses different criteria (alignment length >80% and q-score >30) rather than blastx threshold sweeps

## Inputs

- Coding gene sequences from a mixed mock community (top 20 fungal and top 20 bacterial species)
- Simulated Illumina-format sequencing reads generated by ART
- FunOMIC-P functional database (3.4 million non-redundant fungal proteins, 95% identity CD-HIT clustered)

## Outputs

- Per-combination fungal read hit pass rate for each of the nine Diamond blastx threshold combinations
- A tab-separated table with one row per threshold combination (identity % x coverage %), enabling selection of the optimal setting

## How to apply

Simulate Illumina-format reads from the coding gene sequences of a mixed mock community (e.g. top 20 fungal and top 20 bacterial species) with ART, then align the reads to the FunOMIC-P database (3.4 million non-redundant fungal proteins) with Diamond blastx v2.0.8 holding the e-value fixed at < 10e-10 for every run. Sweep the 3x3 grid of identity percentage (>90%, >95%, >99%) crossed with read coverage (>90%, >95%, >99%) so that nine threshold combinations are evaluated under identical alignment conditions. For each combination, compute the fraction of simulated fungal reads whose hits pass the filters, then assemble the nine pass rates into a single tab-separated table with one row per threshold combination. Select the combination with the highest retained fungal read hit rate; in the FunOMIC-P study this was read coverage >95% with identity percentage >99% (~70% of fungal read hits retained).

## Related tools

- **Diamond blastx v2.0.8** (Aligns simulated Illumina reads (translated search) to the FunOMIC-P protein database under each of the nine threshold combinations) — https://github.com/bbuchfink/diamond
- **ART** (Simulates synthetic next-generation sequencing (Illumina-format) reads from the mock community coding gene sequences for the threshold sweep)
- **FunOMIC** (Supplies the FunOMIC-P functional database and pipeline context against which the blastx thresholds are optimized) — https://github.com/ManichanhLab/FunOMIC

## Examples

```
diamond blastx -d FunOMIC-P.dmnd -q mock_reads.fq -e 1e-10 --id 99 --query-cover 95 -o fungal_hits.tsv
```

## Evaluation signals

- The output table contains exactly all nine combinations: identity >90%, >95%, >99% crossed with coverage >90%, >95%, >99%
- The combination with read coverage >95% and identity percentage >99% shows the highest retained fungal read hit rate (~70%)
- The e-value cutoff is fixed at < 10e-10 across all nine runs so pass-rate differences reflect only identity/coverage filters
- Pass rates are computed only over simulated fungal reads (bacterial reads are excluded from the denominator)
- The table is valid tab-separated text with one row per threshold combination

## Limitations

- Even the optimal threshold leaves ~30% of fungal read hits unmapped, and high inter-kingdom conservation of protein-coding genes means bacterial contamination was not totally preventable with an exceedingly strict mapping threshold
- The optimal threshold is calibrated on simulated fungal/bacterial mock reads; real metagenomes may shift the best identity/coverage trade-off
- FunOMIC's current functional annotation has no bacterial read filtration step before Diamond mapping; it is only proposed for a future update
