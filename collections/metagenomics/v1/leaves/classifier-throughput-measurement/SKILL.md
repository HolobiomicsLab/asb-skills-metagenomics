# classifier-throughput-measurement

## Summary

Benchmarks taxonomic classifier throughput (reads per minute) across the HiSeq, simBA-5, and MiSeq metagenomes using the paper's cache-priming protocol, and computes speedup factors over Megablast and MetaPhlAn to verify claims like 909x and 11x.

## When to use

Use when reproducing or verifying reads-per-minute throughput claims for a metagenomic classifier, or when comparing classifier speed on HiSeq/MiSeq/simBA-5 read sets.

## When NOT to use

- The goal is accuracy assessment (sensitivity/precision at genus or species rank), not speed — use the clade exclusion and rank-measurement experiments instead
- Only a single read set is available and no cache-priming or competitor runs can be performed, so no comparable speedup factor can be computed
- The workload is abundance estimation rather than full read classification — MetaPhlAn-style programs classify only a small percentage of reads, so rpm comparisons of the paper's type do not apply

## Inputs

- HiSeq and MiSeq metagenome FASTQ read sets from NCBI SRA accessions SRS019120, SRS014468, SRS015055
- simBA-5 metagenome read set generated by Mason (Illumina model, 5x mismatch/indel rates)
- Kraken database built with Jellyfish k-mer counts and LCA taxon IDs
- Competitor classifier databases (Megablast/BLAST, MetaPhlAn)

## Outputs

- Per-metagenome wall-clock classification times for each program
- Reads-per-minute throughput table (speed_table.csv) with Kraken and competitor rpm values
- Per-dataset speedup factors of Kraken over Megablast and MetaPhlAn

## How to apply

Retrieve the HiSeq and MiSeq metagenome read sets from the NCBI Sequence Read Archive (accessions SRS019120, SRS014468, SRS015055) and generate the simBA-5 metagenome with the Mason read simulator using its Illumina model with default mismatch and indel rates multiplied by five (average mismatch rate 2%). Build the Kraken database by counting k-mers with Jellyfish and overwriting the 4-byte count spaces with LCA taxonomic IDs. Before any timed run, read all database files into memory three times to populate the operating system cache, matching the paper's protocol; apply the same priming to every competitor (Megablast, the fastest BLAST mode, and MetaPhlAn). Run Kraken on each metagenome, record wall-clock time, and compute reads per minute; repeat for each competitor and derive per-dataset speedup factors. Validate against the paper's reported throughput thresholds (>1.5M rpm HiSeq, >1.3M rpm simBA-5, >890K rpm MiSeq) and the 150-240x speedup range over Megablast.

## Related tools

- **Kraken** (primary classifier whose reads-per-minute throughput is measured on the three metagenomes) — http://ccb.jhu.edu/software/kraken/
- **Megablast** (fastest BLAST mode; nearest competitor timed under the same cache-priming protocol for speedup factors)
- **MetaPhlAn** (abundance estimation program timed for the 11x speed comparison)
- **Mason** (read simulator used to generate the simBA-5 metagenome with 5x default mismatch and indel rates)

## Examples

```
kraken --db $KRAKEN_DB --threads 8 --fastq-input HiSeq_metagenome.fastq > kraken_out.txt  # time wall-clock to compute rpm
```

## Evaluation signals

- Kraken throughput on the HiSeq metagenome exceeds 1.5 million reads per minute
- Kraken throughput on simBA-5 exceeds 1.3 million rpm and on the MiSeq metagenome exceeds 890,000 rpm
- Computed Kraken/Megablast speedup ratios fall within the reported 150-240x range; deviations flag output for expert review
- All database files were read into memory three times before every timed run, for Kraken and each competitor alike
- Measured competitor throughput is consistent with the paper's claims (909x vs Megablast overall; 11x vs MetaPhlAn)

## Limitations

- Timing depends on operating system cache population; without the triple pre-load protocol results are not comparable
- Only wall-clock speed is measured; accuracy is a separate experiment (clade exclusion, rank measurement)
- Jellyfish and Mason versions are not specified in the paper, so exact tool versions must be chosen and recorded by the reproducer
- Throughput depends on database size; MiniKraken 4-GB databases (first 18 of every 19 records removed) will show different speeds
