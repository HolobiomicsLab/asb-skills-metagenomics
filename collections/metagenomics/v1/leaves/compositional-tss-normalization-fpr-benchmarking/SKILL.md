# compositional-tss-normalization-fpr-benchmarking

## Summary

A negative-control benchmarking skill that quantifies how systematic sequencing-depth differences between time points inflate false positives when compositional TSS-normalized count data are fitted with linear models, using LongDat's negative-binomial pipeline on rarefied tables as the FPR-controlled comparator.

## When to use

Use when benchmarking normalization/model choices on longitudinal microbiome count data with simulated or real depth bias, specifically to measure false positive rates on truly-null (zero effect size) features under rarefaction vs TSS normalization.

## When NOT to use

- When features have genuine non-zero time effects — this skill is designed for negative-control (null) data and only estimates false positive rates, not power or true discovery
- When the data are already relative-abundance/TSS-normalized tables rather than raw counts — LongDat's negative-binomial count mode and rarefaction assume count input
- When the question is tool benchmarking for accuracy or runtime against MaAsLin2, ANCOM, lgpr or ZIBR rather than normalization-induced FPR under depth bias

## Inputs

- Simulated longitudinal count tables (features x samples, two time points, zero effect size) generated by SparseDOSSA2
- Six dataset versions with systematically varying sequencing depths
- LongDat master table built from metadata and feature tables via make_master_table()
- Nominal alpha significance threshold (e.g. 0.05)

## Outputs

- Per-feature LongDat result tables with Signal, p-value and EffectSize columns (plus randomized control table for count data)
- Per-setting false positive rates over truly-null features for rarefied negative-binomial and non-rarefied linear/TSS pipelines
- FPR contrast table across the six depth versions
- Supplementary Fig. S9-style comparison figure

## How to apply

Generate negative-control longitudinal count tables with SparseDOSSA2 using zero effect size across two time points, creating six dataset versions that differ systematically in sequencing depth. Rarefy each simulated count table to its designated depth so all samples within a version share a common library size, then run LongDat's count-data longitudinal pipeline (longdat_cont() or longdat_disc(), negative-binomial mode) with a set seed, since reproducible randomized control tests require setting the seed when data_type equals 'count'. As the comparator, fit linear models on TSS-transformed versions of the non-rarefied count tables. Compute the false positive rate per setting as the fraction of truly-null features called significant at the nominal alpha threshold (e.g. 0.05) across all six depth versions, tabulate the FPR contrast between the rarefied negative-binomial and non-rarefied linear/TSS settings, and render a Supplementary Fig. S9-style comparison figure. The rationale is that depth-driven compositionality artifacts leak into TSS-transformed linear-model p-values, while rarefaction plus negative-binomial modeling preserves near-nominal type I error on null data.

## Examples

```
set.seed(123); test_cont <- longdat_cont(input = LongDat_cont_master_table, data_type = "count", test_var = "Day")
```

## Evaluation signals

- Rarefied negative-binomial FPR is near zero (at or below the nominal alpha level) across all six sequencing-depth versions
- Linear/TSS FPR on non-rarefied data is markedly elevated under large sequencing-depth variation, matching the qualitative pattern of Supplementary Fig. S9
- Seed was set before running longdat_cont()/longdat_disc() with data_type = 'count' so the randomized control table is reproducible
- FPR per setting is computed only over features that are truly null (zero effect size in the SparseDOSSA2 simulation)
- Every sample within a dataset version shares a common library size after rarefaction, verifiable by checking column sums of the rarefied table

## Limitations

- The elevated FPR under linear/TSS normalization emerges only under large sequencing-depth variation between time points; with uniform depths the contrast may vanish
- Conclusions are for negative-control (zero effect size) data; skill does not measure sensitivity/power to real effects
- When data_type equals 'count', the randomized control test is stochastic — without setting a seed results are not reproducible
