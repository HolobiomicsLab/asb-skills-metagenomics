# containerized-bioinformatics-deployment

## Summary

Deploy fully automated Nextflow-based population genomics pipelines (nf-core-style, DSL2) whose software dependencies are resolved automatically inside containers or environments (Conda/mamba, Singularity, Docker), so users install only Nextflow, Java, and one container system.

## When to use

Use when a population genomic analysis on biallelic SNP data (VCF or PLINK binary) must be run reproducibly on a local Linux machine or HPC cluster without manually installing each analysis tool or lacking HPC admin privileges.

## When NOT to use

- When only a single ad-hoc tool is needed and installing it directly is simpler than standing up Nextflow, Java, and a container system
- When the data are not biallelic SNP genotypes in VCF or PLINK binary format (scalepopgen's stated input scope)
- When the analysis requires non-Linux platforms — the pipeline runs on any Linux operating system but this is its stated requirement

## Inputs

- Chromosome-split, tabix-indexed VCF files listed in a comma-separated vcf_input.csv sheet (chrom,vcf,vcf_idx header)
- PLINK binary files (bed/bim/fam) listed in a comma-separated .p.csv sheet (prefix,bed,bim,fam header)
- Tab-delimited two-column sample map file ending in '.map' mapping individual IDs to population IDs
- YAML parameters file, preferably generated by the scalepopgen-cli
- Bundled small test dataset (via -profile test) or paper dataset (via -profile test_full)

## Outputs

- Consolidated MultiQC (v1.19) final HTML report compiling visualizations of each analysis sub-workflow
- Nextflow HTML execution report with per-process completion status and computational resource usage
- Sub-workflow results from filtering/basic statistics, genetic structure (PCA, ADMIXTURE, IBS/FST), TreeMix phylogeny, and selection scans (Tajima's D, Pi, FST, SweepFinder2, iHS/XP-EHH)
- Interactive Plotly/Bokeh visualizations produced by embedded Python/R scripts
- citation_ folder with BibTeX references generated by the CLI

## How to apply

Install only three dependencies — Nextflow, Java, and one container/environment system (Conda, mamba, Singularity, or Docker; the README recommends mamba) — then clone the scalepopgen repository; Nextflow automatically downloads the rest of the tools. Prepare inputs as chromosome-split, tabix-indexed VCFs listed in a comma-separated sheet (vcf_input.csv with chrom,vcf,vcf_idx headers) or as PLINK bed/bim/fam files listed in a .p.csv sheet, plus a two-column tab-delimited sample.map of individual and population IDs. Generate the YAML parameter file with the scalepopgen-cli, then launch with 'nextflow run scalepopgen/ -profile <docker/singularity/conda/mamba> -params-file <path/to/parameters.yml> -qs <max processes>'; custom config files may be supplied with -c for everything except parameters. Validate the setup first with the bundled '-profile test' minimal dataset, and reproduce the paper's cattle results (442 samples, 30 breeds, ~25 million SNPs) with '-profile test_full'. Containerization rationale: nf-core-style templating isolates each tool in its own containerized module, letting the pipeline run identically on local and HPC systems.


- The CLI-generated citation_ folder exists and contains the relevant BibTeX references

## Limitations

- Users must pre-install Nextflow, Java, and a container/environment system; only the remaining tools are downloaded automatically
- VCF chromosome names must not contain punctuation marks, and all VCFs must be split by chromosome and tabix-indexed
- Custom config files supplied with -c cannot override pipeline parameters, which must come from the -params-file YAML
