# dirichlet-tree-multinomial-regression

## Summary

Fit Dirichlet-tree multinomial (DTM) regression models with Bayesian variable selection via the MicroBVS R package to identify covariates associated with compositional microbial abundance data, accommodating phylogenetic tree structure and alternative inclusion priors (Beta-Binomial or MRF-based).

## When to use

Use when the input is compositional count data (e.g., microbiome taxa) paired with covariates, and the goal is variable selection of covariate-by-branch associations while respecting a known or unknown phylogenetic/graph structure.

## When NOT to use

- The response data are not compositional counts (e.g., already normalized/relative abundance feature tables) — the DTM likelihood expects count compositions
- No covariates are of interest and the goal is purely unsupervised ordination or clustering rather than covariate-branch association selection
- A known phylogenetic tree is unavailable and MRF/DM structure is not the target — the DTM models accommodate tree-like structure between the compositional data

## Inputs

- Compositional count data (e.g., microbial taxa abundance table) with a phylogenetic tree (ape phylo object)
- Covariate matrix (e.g., 50 covariates, possibly with block covariance/correlation structure)
- Simulated DTM data generated by MicroBVS simulate_DTM (subject count, covariate count, tree, rho, seed)
- Prior specification: Beta-Binomial inclusion prior hyperparameters (a, b) or MRF prior type ('MRF_unknown')

## Outputs

- Posterior samples of covariate inclusion indicators per tree branch (from DTMbvs_R MCMC)
- Selected branch-by-covariate associations from selected_DTM at MPPI >= 0.50
- Recovered adjacency matrix of covariate relations (from MRF_unknown edge-inclusion probabilities)
- Results CSV of selections and recovery counts (true positives / false positives)

## How to apply

Install MicroBVS in R after its dependencies (Rcpp, RcppArmadillo, MCMCpack, mvtnorm, ggplot2, devtools, ape, igraph) using devtools::install_github('mkoslovsky/MicroBVS', build_vignettes = TRUE). Simulate or load compositional count data with simulate_DTM (e.g., 100 subjects, 50 covariates, a 5-leaf phylogenetic tree, correlation rho = 0.3), then run the DTMbvs_R C++-backed sampler via its R wrapper, choosing a Beta-Binomial inclusion prior (e.g., a = 0.1, b = 0.9) or an MRF-based prior on covariates, and discard burn-in iterations (e.g., 2500) before summarizing. Extract selected branch-by-covariate associations with selected_DTM at an MPPI threshold of 0.50; for unknown covariate structure, run DMbvs_R with prior='MRF_unknown' and threshold posterior edge-inclusion probabilities to recover the adjacency matrix among covariates. Convergence is dependent on covariate correlation structure and model sparsity, so validate recovery against planted (true) associations and report true/false positive counts.

## Evaluation signals

- In the vignette DTM simulation (100 subjects, 50 covariates, 5-leaf tree, rho=0.3, Beta-Binomial a=0.1 b=0.9, 2500 burn-in), selection at MPPI >= 0.50 recovers 9 of 15 planted branch-by-covariate associations with zero false positives
- With prior='MRF_unknown' on block-covariance simulated data, the model identifies edges with sigma_ij = 0.7; the recovered adjacency matrix must be square, symmetric, and binary over the simulated covariates
- For the joint DM-LM model (dm_lm_bvs_R with 10,000 iterations thinned by 10, burn-in 500, threshold 0.5), selected_zeta and selected_xi should agree with the 10 true active covariates and first 10 active balances
- Output CSVs must exist, parse as valid CSV, and contain the expected selection/recovery columns
- Report convergence behavior, since the article notes convergence depends on covariate correlation structure and model sparsity

## Limitations

- Convergence of the DTM MCMC algorithm is highly dependent on the correlation structure between covariates and count data, as well as the sparsity level of the model
- For the joint DM-LM model, a revision (as of 9/6/23) replaced a Gibbs update of auxiliary parameters c_ij with an MH update, increasing computation time; a 'full' variant and a partial-update 'rate' parameter (>= 0.50 in simulation) mitigate this
