# insertion-sequence-database-benchmarking

## Summary

Benchmarks a de novo insertion sequence (IS) catalogue against a reference IS database (ISfinder) by BLASTing every catalogue sequence and stratifying hits into strict/loose homology and novel bins, quantifying how much of the catalogue is previously characterized.

## When to use

Reference for quantifying the fraction of a newly built IS catalogue with known homologs, e.g. after running Palidis on metagenomes and producing a non-redundant FASTA of insertion sequences to be annotated against ISfinder.

## When NOT to use

- The catalogue contains ISs lacking inverted terminal repeats, since the source ISC was generated by Palidis which only discovers ISs with ITRs and the benchmark design assumes comparable catalogue content.
- A local, reproducible BLAST workflow is required — the paper used ISfinder's online BLAST service, so results depend on database version and web-service parameters at the query date.
- The goal is de novo IS discovery from metagenomic reads rather than annotating an existing IS catalogue against a reference database.

## Inputs

- FASTA file of insertion sequences (e.g. ISC v1.0.0, 879 ISs from github.com/blue-moon22/ISC)
- ISfinder database accessed via its online BLAST service (e-value cutoff 0.01, default parameters)

## Outputs

- Summary table (e.g. isfinder_homology_benchmark.csv) with counts of strict hits (e-value <1e-50), loose hits (0.01>e-value >=1e-50), and novel sequences
- Per-sequence homology classification (strict / loose / novel) for every catalogue IS

## How to apply

Download the catalogue FASTA (e.g. the 879-IS ISC v1.0.0 from github.com/blue-moon22/ISC) and query each sequence against ISfinder's online BLAST service with an e-value cutoff of 0.01 and default parameters (as of 7 October 2022 in the paper). Classify each catalogue sequence into three bins: strict homology when e-value < 1e-50, loose homology when 0.01 > e-value >= 1e-50, and novel when no hit passes the 0.01 threshold. Tabulate the counts per bin and report the fraction of the catalogue with ISfinder hits (e.g. 360 of 879, 41.0%, splitting into 60 strict + 300 loose, leaving 519 novel) as a summary CSV. The binning rationale is that strict hits indicate near-certain known IS identity while loose hits indicate remote homology worth manual curation.

## Related tools

- **Palidis** (Pipeline that generated the IS catalogue being benchmarked; its FASTA output of insertion sequences is the query input) — https://github.com/blue-moon22/palidis
- **ISfinder** (Reference database of known transposable elements queried via its online BLAST service to classify catalogue ISs as strict, loose, or novel)
- **COBS** (Alternative compact bit-sliced signature index of 661 405 microbial genomes that the paper uses for querying/catalogue origin prediction, mentioned alongside ISfinder)

## Examples

```
# Download ISC FASTA (879 ISs), then query against ISfinder online BLAST (e-value cutoff 0.01, defaults) and bin hits:
# strict: e-value < 1e-50; loose: 0.01 > e-value >= 1e-50; novel: no hit <= 0.01
curl -LO https://github.com/blue-moon22/ISC/releases/download/v1.0.0/ISC.fasta && python classify_isfinder_hits.py --query ISC.fasta --cutoff 0.01 --strict 1e-50 --out isfinder_homology_benchmark.csv
```

## Evaluation signals

- Counts must partition the catalogue exactly: strict + loose + novel = total ISs (879 = 60 + 300 + 519).
- Fraction with ISfinder hits should match the reported 41.0% (360/879) when reproducing ISC v1.0.0 with e-value cutoff 0.01.
- Every sequence must fall in exactly one bin: strict (e-value <1e-50), loose (0.01 > e-value >= 1e-50), or novel (no hit at 0.01) with no double-counting.
- The summary table (isfinder_homology_benchmark.csv) should be produced with per-bin counts consistent with the classification thresholds used.

## Limitations

- Benchmark results depend on the ISfinder database version and web BLAST parameters at the query date (the paper used defaults as of 7 October 2022).
- ISC v1.0.0 only contains common DDE-type ISs with ITRs of 25 or more nucleotides (ITRs as short as ten nucleotides are missed at default settings), so the benchmark under-represents ITR-lacking or short-ITR ISs.
- ISC v1.0.0 was built only from healthy human oral cavity and stool metagenomes, limiting generalization of the homology fractions to isolates from other sources.
- No changelog is available for the ISC resource, complicating reproducibility across releases.
