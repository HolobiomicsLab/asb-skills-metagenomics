# kraken2-taxonomy-charting

## Summary

Profile metagenomic reads with Kraken2 (MiniKraken2_V1 by default) inside the MetaPhage Nextflow pipeline and surface the resulting taxonomy as charts and filterable tables in the MultiQC-generated interactive HTML report.

## When to use

Use when a virome or metagenomics project needs read-level taxonomic profiling (Kraken2 with a miniKraken database) and its visualization — Kraken2 charts, taxonomy tables, and PhyloSeq objects — inside a MetaPhage HTML report.

## When NOT to use

- Input is already a taxonomy abundance table or PhyloSeq object — Kraken2 read profiling would only duplicate existing classification
- The goal is vOTU-level phage identification and miner comparison (VirFinder/VirSorter/Phigaro/VIBRANT), not read-level community profiling
- Reference-genome-free viromes where a Kraken2 database is a poor fit and assembly-based gold-standard identification of viral contigs is preferred

## Inputs

- Cleaned paired-end metagenome FASTQ reads (post-fastp trimming, mean quality 15, phiX removed)
- Kraken2 database (MiniKraken2_V1 default, or user-defined k2 index)
- Project configuration file (project.conf) generated by newProject.py with CSV metadata

## Outputs

- Kraken2 read-classification output and taxonomy profile per sample
- MultiQC interactive HTML report (report/index.html) containing Kraken2 taxonomy charts
- Taxonomy table and PhyloSeq objects assembled from the taxonomy analysis outputs

## How to apply

Create a project configuration with newProject.py pointing at the FASTQ reads and CSV metadata, then run the MetaPhage Nextflow pipeline (nextflow run main.nf -c project.conf) without skipping the read-profiling step, so Kraken2 classifies reads against the default MiniKraken2_V1 database (or a user-supplied Kraken2 database from benlangmead.github.io/aws-indexes/k2). Upstream, quality trimming with fastp (cut_mean_quality 15) and phiX removal run by default, so the taxonomy step receives cleaned reads. Keep the report step enabled (--skip_report defaults to false) so MultiQC assembles Kraken2 charts together with fastp_qc, assembly, mining, cd-hit and diversity outputs into report/index.html, alongside the count table, taxonomy table, and PhyloSeq objects. Validate that the report renders the Kraken2 charts and taxonomy visualizations and that the structure matches the authors' deposited figshare report (doi.org/10.6084/m9.figshare.20424705).

## Examples

```

```

## Evaluation signals

- report/index.html exists and renders as an interactive HTML report with Kraken2 taxonomy charts present among the panels
- Taxonomy outputs feed the MultiQC report assembled from fastp_qc, assembly, mining, taxonomy, cd-hit and diversity analysis outputs
- Taxonomy table and PhyloSeq objects are present in the report directory alongside the count table
- Report structure and key figures match the authors' deposited v.0.3.2 output on figshare (doi.org/10.6084/m9.figshare.20424705)
- Taxonomy profile reflects reads cleaned by fastp (cut_mean_quality 15) and phiX removal, not raw FASTQ

## Limitations

- MiniKraken2_V1 is a reduced database, so read classification sensitivity is bounded by its content; a user-defined Kraken2 database can be substituted
- Taxonomic classification at the read level is a profiling step and does not provide vOTU-level phage identification or CheckV quality assessment of viral contigs
- BLAST- or database-based classification can leave large proportions of sequencing data unclassified and uncharacterized
