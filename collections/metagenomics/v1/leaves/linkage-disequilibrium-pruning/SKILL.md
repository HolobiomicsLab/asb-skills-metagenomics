# linkage-disequilibrium-pruning

## Summary

Prune biallelic SNP datasets for linked sites using user-defined LD parameters of Plink2 within the scalepopgen Nextflow workflow, so that downstream population-genomic analyses (e.g., structure inference) are not biased by linkage. In the paper's cattle case study, LD-based filtering reduced the filtered data set to 129,357 SNPs.

## When to use

Use when a genome-wide biallelic SNP dataset (VCF or PLINK binary) is being prepared for analyses that assume quasi-independent markers (e.g., ADMIXTURE, PCA) and SNPs must be pruned by linkage disequilibrium before analysis.

## When NOT to use

- The downstream analysis does not require LD-pruned markers (LD pruning is optional/recommended, not mandatory, in scalepopgen).
- Input data is raw variant calls that have not yet passed the mandated sample filtering before site filtering order of the filtering sub-workflow.

## Inputs

- CSV input sheet (.csv) listing chromosome-split, tabix-indexed VCF files (chrom, vcf, vcf_idx columns) or PLINK binary files (.p.csv with prefix, bed, bim, fam)
- Tab-delimited sample map file (.map) mapping individual IDs to population IDs
- YAML parameters file specifying user-defined LD pruning parameters of Plink2

## Outputs

- LD-pruned SNP set carried forward as PLINK binary (BED) genotype files for downstream analyses
- Intermediate pruned dataset consumed by structure/phylogeny/selection sub-workflows (case study: 129,357 SNPs)

## How to apply

After the mandatory sample filtering followed by site filtering (using Plink v1.9, Plink2, and Vcftools v0.1.16, e.g., genotype missingness and MAF criteria), optionally apply LD-based pruning using the user-defined LD parameters of Plink2 before supplying the input file to its respective analysis. In scalepopgen this step sits inside the 'filtering and basic statistics' sub-workflow, which takes a CSV sheet of chromosome-split, tabix-indexed VCF files (or PLINK BED/BIM/FAM) plus a tab-delimited sample map (.map) of individual-to-population assignments, with all parameters supplied via a YAML file generated by the CLI. The pruning operates on the filtered genotype data and precedes conversion/emission of PLINK binary (BED) files used downstream (e.g., running ADMIXTURE on the bed file). Tune the LD window, step, and r^2 thresholds via the YAML parameters rather than defaults, since the paper describes them as user-defined. In the case study, pruning the ~23.4 million filtered SNPs from 269 samples yielded 129,357 SNPs, providing a concrete scale expectation.

## Related tools

- **PLINK** (Plink2 performs the user-defined LD-based pruning of sites and conversion to binary PED (BED) format) — https://github.com/Popgen48/scalepopgen
- **Nextflow** (Workflow management system orchestrating the filtering sub-workflow that contains the LD pruning step) — https://github.com/Popgen48/scalepopgen

## Examples

```
nextflow run scalepopgen/ -profile docker,singularity -params-file parameters.yml -qs 10
```

## Evaluation signals

- The pruned SNP count is far smaller than the filtered input: in the case study, ~23.4 million filtered SNPs were reduced to 129,357 SNPs by LD-based filtering.
- LD pruning runs only after sample filtering and site filtering have completed, in that mandated order.
- Pruned output is emitted as PLINK binary (BED) files and accepted by downstream tools such as ADMIXTURE without format errors.
- The pruning parameters (window, step, r^2) match the values the user set in the YAML parameters file created with the scalepopgen CLI.

## Limitations

- LD pruning is optional and analysis-dependent — it is applied 'before supplying the input file to its respective analysis', so it must not be assumed for all sub-workflows.
- Aggressive LD pruning drastically reduces marker count (from millions to ~129k in the case study), which may not suit analyses requiring dense genome coverage.
- VCF inputs must be split by chromosome, tabix-indexed, and chromosome names must not contain punctuation marks.
