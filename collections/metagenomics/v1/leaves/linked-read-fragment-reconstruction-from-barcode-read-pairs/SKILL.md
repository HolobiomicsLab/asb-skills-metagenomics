# linked-read-fragment-reconstruction-from-barcode-read-pairs

## Summary

Reconstructs original input DNA fragments from 10x Linked-Read data by grouping barcode-proximal read pairs, then subsamples reads per fragment to a target per-fragment short-read coverage (CR) so Linked-Read libraries with different parameters become comparable (Rid sets).

## When to use

Use when high-coverage 10x Linked-Read FASTQs with different library parameters (CF, CR, fragment length) must be normalized to matched CR before assembly comparison, or when simulating realistic Linked-Reads.

## When NOT to use

- Input reads lack 10x barcodes / GemCode partitioning information (standard Illumina WGS) — barcode-proximal grouping cannot be performed
- Libraries already share the same CR and fragment-length parameters, so subsampling for comparability is unnecessary
- The goal is variant calling from the full-depth data rather than generating matched-depth Linked-Read sets for assembly comparison

## Inputs

- Raw 10x Chromium paired-end Linked-Read FASTQ files (R1/R2)
- hg38 human reference genome sequence
- LRTK-SIM configuration file specifying CR, CF, N_FP, Mu_F, SR, Error_rate, Mu_IS, Std_IS, Hap
- Optional: diploid haplotype FASTA files generated by gen_fasta.py from VCF + reference

## Outputs

- Gzipped R1/R2 FASTQ pairs subsampled to the target CR (e.g. X_S1_L001_R1_001.fastq.gz and X_S1_L001_R2_001.fastq.gz)
- Comparable Linked-Read sets (Rid) with matched per-fragment read coverage across libraries
- Inferred input DNA fragments (>=2 read pairs, >=2 kb, terminated at >50 kb gaps) grouped into partitions

## How to apply

Align the raw 10x paired-end reads to the hg38 human reference with the 10x Long Ranger pipeline and remove PCR duplicates in a barcode-aware manner using Long Ranger's duplicate marking. Reconstruct input DNA fragments by grouping barcode-proximal read pairs, terminating fragment extension at gaps >50 kb, and retaining only fragments supported by >=2 read pairs and >=2 kb in length; discard partitions containing fewer than 3 inferred fragments. Then randomly subsample read pairs within each retained fragment until the target short-read coverage per fragment (CR) is met, producing gzipped R1/R2 FASTQ pairs. In the LRTK-SIM simulator the same logic is driven by config parameters CR (coverage of short reads for each fragment) and CF (coverage of long DNA fragments), with the simulated gzipped FASTQs written as X_S1_L001_R1_001.fastq.gz and X_S1_L001_R2_001.fastq.gz. Rationale: the paper's parameter-space study requires Linked-Read sets (Rid) with matched CR across libraries so that assembly quality differences reflect CF and fragment length rather than uneven per-fragment read coverage.

## Examples

```
python LRTK-SIM.py ./diploid_config
```

## Evaluation signals

- Verification that the gzipped FASTQ pair exists and is well-formed
- Realized per-fragment read coverage qualitatively matches the configured target CR (the paper reports no numeric tolerance)
- Partitions with fewer than 3 inferred fragments are absent from the subsampled output
- No inferred fragment shorter than 2 kb or supported by fewer than 2 read pairs is retained; extensions never span gaps >50 kb
- Simulated/subsampled data are accepted by the official 10x Long Ranger and Supernova pipelines

## Limitations

- The paper reports no numeric tolerance for the match between realized and target CR, so acceptance is a qualitative check
- Only ~20–40% of original long fragment sequence is generally captured per 10x partition due to partition-level amplification, so inferred fragments are incomplete proxies of the original DNA molecules
- Loss of barcode specificity for fragments spanning repetitive sequences can affect fragment inference for extremely long fragments
