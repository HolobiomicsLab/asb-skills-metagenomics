# metagenomic-short-read-assembly

## Summary

Assembles quality-controlled metagenomic short reads (FASTQ) per sample with MEGAHIT within the MetaPhage Nextflow pipeline, producing contigs/scaffolds that are subsequently mined for viral signal by multiple phage miners (DeepVirFinder, VirSorter2, VIBRANT, Phigaro).

## When to use

Use when raw shotgun metagenomic or virome FASTQ reads must be converted into assembled contigs before viral contig mining, e.g. reproducing the Liang et al. 2020 infant stool 59-sample vOTU analysis with MetaPhage.

## When NOT to use

- Input is already assembled contigs or a vOTU catalogue — the assembly step would be redundant; skip directly to mining/dereplication
- Data are long reads (PacBio/Nanopore) — MEGAHIT in this pipeline is designed for short Illumina-style reads
- The goal is strain-resolved or single-sample isolate assembly rather than metagenomic contig generation for viral mining

## Inputs

- Quality-controlled, trimmed paired-end FASTQ reads (per sample, from fastp with cut_mean_quality 15 and phiX removal)
- Project configuration file (project.conf) generated by newProject.py from the reads directory and CSV metadata

## Outputs

- Per-sample assembled contigs/scaffolds from MEGAHIT
- Downstream consensus viral scaffolds dereplicated into vOTUs (≥3,000 bp after --minlen 3000 filtering)

## How to apply

After quality control and trimming with fastp (sliding-window trimming with cut_mean_quality 15) and phiX contaminant removal, assemble quality-controlled reads per sample with MEGAHIT as the assembly module of MetaPhage, which is orchestrated as a Nextflow pipeline with containerized tools (Singularity v3.7.1, Docker, or Conda). For virome datasets, run MetaPhage with the --virome option so that nonviral scaffolds are removed and sensitivity is increased for virome data. The resulting per-sample assemblies feed the phage-mining step, whose consensus viral scaffolds are dereplicated with CD-HIT-EST (identity 0.95, word size 9, coverage 0.85, --minlen 3000) into vOTUs. Correctness is judged by whether the downstream workflow reproduces reported figures, e.g. 14,274 vOTUs on the Liang et al. shotgun dataset with 4,666 vOTUs containing more than 10 open reading frames.

## Examples

```
python newProject.py -i reads/ -m metadata.csv -v variable -s project.conf  # then: nextflow run MattiaPandolfoVR/MetaPhage -c project.conf --virome
```

## Evaluation signals

- Assemblies exist for every input sample (59 samples in the Liang et al. shotgun dataset) and are produced from the fastp-trimmed, phiX-decontaminated reads rather than raw reads
- Downstream vOTU count after CD-HIT-EST dereplication (0.95 identity, 0.85 coverage, --minlen 3000) is in the expected range — 14,274 vOTUs reported for this dataset, 4,666 with >10 ORFs
- Miner-comparison summary (upSet plot) shows DeepVirFinder as the highest predictor with 10,508 predictions and 2.3% of vOTUs predicted by all five miners, matching the reported figures
- The --virome option was applied for the virome dataset, confirming nonviral scaffolds were removed before mining
- vOTU counts and richness pattern (month 0 to 4) show high concordance with the original Liang et al. publication

## Limitations

- Different phage miners yield very different vOTU counts; CheckV showed the large difference was due to predictions of more partial and low-quality genomes
- Users should be mindful of the biases inherent to virome analyses, including recall/precision trade-offs in virus prediction
- Downstream vConTACT2 network is rebuilt every time new data are added, and the all-versus-all protein comparison against large reference databases is time-consuming
