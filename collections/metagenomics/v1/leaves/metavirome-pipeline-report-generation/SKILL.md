# metavirome-pipeline-report-generation

## Summary

Generate an exhaustive interactive HTML report for a virome analysis using MetaPhage's Nextflow pipeline, whose final MultiQC-based report step assembles summary visualizations and interactive filterable tables (miner comparison, Kraken2 charts, diversity plots, metaQUAST statistics) from all upstream module outputs.

## When to use

Use when a paired-end virome/metagenome FASTQ dataset (e.g. VLP-enriched reads with a CSV metadata file) must be processed end-to-end and delivered as a single interactive HTML report comparing phage miners, taxonomy, and diversity.

## When NOT to use

- The task is only a targeted re-analysis of already-deposited report outputs rather than a full reads-to-report run — downstream comparison alone does not need re-executing the pipeline.
- Data are single-end or non-metagenomic reads, since newProject.py infers paired-end metagenome inputs automatically and the modules (virome-aware mining, phiX removal) target virome data.
- Only quality trimming or phiX filtering is needed without the assembled report — run the specific filtering modules instead of the full report-generating pipeline.

## Inputs

- Paired-end metagenomic FASTQ reads (e.g. VLP-enriched infant virome samples)
- CSV metadata file with sample annotations and a chosen main metadata variable
- Project configuration file (project.conf) generated by newProject.py
- MetaPhage reference databases: Inphared, Kraken2/minikraken (MiniKraken2_V1), Phigaro, PhiX, VIBRANT, VirSorter

## Outputs

- Interactive HTML report (report/index.html) assembled by MultiQC
- Miner Comparison panel showing number of vOTUs per phage mining tool (VirFinder, VirSorter, Phigaro, VIBRANT)
- Kraken2 taxonomy charts and metaQUAST assembly statistics panels
- Diversity plots (PhyloSeq objects)
- Interactive filterable tables: count table, taxonomy table
- vOTU multifasta, protein multifasta, and GFF annotation files

## How to apply

Create a project configuration with newProject.py pointing at the directory of paired-end VLP metagenome reads plus the CSV metadata file and selecting the main metadata variable, then run the Nextflow pipeline (nextflow run main.nf -c project.conf). Enable the full module chain: fastp quality trimming (cut_mean_quality 15), phiX removal, Kraken2 read profiling (MiniKraken2_V1 default database), Megahit assembly with metaQUAST overview, the four phage miners (VirFinder, VirSorter, Phigaro, VIBRANT), CD-HIT-EST dereplication (0.95 identity, 0.85 coverage), and diversity analysis. Leave the report step enabled (--skip_report defaults to false) so MultiQC assembles the interactive HTML report from the fastp_qc, assembly, mining, taxonomy, cd-hit and diversity outputs. Rationale: a single reads-to-report run removes the tool-format incompatibilities and dependency clashes that the authors identify as a major drawback of virome analysis, while the miner-comparison panel exposes how differently VirFinder, VirSorter, Phigaro, and VIBRANT score the same contigs.

- **MetaPhage** (reads-to-report Nextflow pipeline whose report module assembles the final interactive HTML report) — https://github.com/MattiaPandolfoVR/MetaPhage

## Examples

```
python newProject.py --path ./vlp_reads --metadata samples.csv --variable month && nextflow run main.nf -c project.conf
```

## Evaluation signals

- report/index.html exists in the report directory and renders as an interactive HTML report with the expected panels (miner comparison, diversity plots, Kraken2 charts, metaQUAST statistics)
- Miner Comparison panel reports vOTU counts for all four miners (VirFinder, VirSorter, Phigaro, VIBRANT), enabling direct comparison of each software's performance
- Interactive filterable tables are present: count table, taxonomy table, and PhyloSeq diversity objects
- Report output files (vOTU multifasta, protein multifasta, GFF annotation) are present alongside the visualizations
- Generated report structure and key figures match the authors' deposited full output (v.0.3.2, figshare doi.org/10.6084/m9.figshare.20424705)

## Limitations

- Users are urged to be mindful of biases inherent to virome analyses; the recall/precision trade-off in virus prediction affects miner counts shown in the report (e.g. CheckV showed large vOTU-count differences were due to partial and low-quality genome predictions)
- vConTACT2 network classification is time-consuming: the network is rebuilt every time new data are added, and the all-versus-all protein comparison against large reference databases (e.g. INPHARED) extends runtime
- vConTACT2 does not directly classify a vOTU; without graphanalyzer the classification is left to extensive manual inspection
