# metavirome-read-quality-control

## Summary

Quality-control and contaminant-filtering of raw metagenomic/virome reads as implemented in the MetaPhage pipeline: fastp sliding-window quality trimming with phiX174 contaminant removal prior to assembly and phage mining.

## When to use

Use when raw FASTQ reads from shotgun metagenome or virome sequencing must be quality-trimmed and decontaminated (e.g., phiX spike-in) before assembly and viral contig mining.

## When NOT to use

- Input is already quality-trimmed and decontaminated FASTQ (re-running trimming could over-trim; pass --skip_qtrimming instead)
- Data contain a contaminant other than phiX174 without providing a user-defined genome for the filtering step
- Working with long reads (Nanopore/PacBio) — fastp targets short reads such as Illumina NovaSeq/MGI data

## Inputs

- Raw paired-end FASTQ reads (e.g., 59 shotgun metagenome samples from Liang et al. 2020 infant stool)
- Project configuration generated by newProject.py (-i reads directory, -m CSV metadata, -v metadata variable, -s project.conf)
- phiX174 reference genome (default contaminant target)

## Outputs

- Quality-trimmed, phiX-decontaminated FASTQ files per sample
- fastp QC/filtering reports (JSON and HTML) with Q20/Q30 and trimming statistics
- Cleaned reads ready for per-sample MEGAHIT assembly

## How to apply

Run fastp with sliding-window trimming where per-read mean quality falls below a user-defined threshold set with --cut_mean_quality (15 by default in MetaPhage), keeping paired-end synchronization for Illumina reads. Remove contaminant reads mapping to the phiX174 genome (the SeqScreener step, default contaminant) unless --keep_phix is set; quality trimming is enabled by default and can be skipped with --skip_qtrimming. For virome datasets such as the Liang et al. 2020 infant stool samples, enable the --virome option so nonviral scaffolds are removed downstream, increasing sensitivity for virome data. The rationale is that low-quality bases and phiX spike-in reads otherwise propagate into MEGAHIT assemblies and inflate false viral contig predictions by the miners (DeepVirFinder, VirSorter2, VIBRANT, Phigaro). Outputs are cleaned FASTQ files plus fastp QC reports (JSON/HTML) that feed the per-sample assembly step of the reads-to-report pipeline.

## Related tools

- **fastp** (Sliding-window quality trimming of reads with --cut_mean_quality 15 by default) — https://github.com/OpenGene/fastp
- **MetaPhage** (Nextflow pipeline orchestrating QC, phiX removal, and the --virome nonviral-scaffold filtering option) — https://github.com/MattiaPandolfoVR/MetaPhage

## Examples

```
nextflow run MattiaPandolfoVR/MetaPhage -profile standard --reads reads/ --metadata samples.csv --variable group --virome
```

## Evaluation signals

- fastp JSON/HTML reports show post-trimming Q20/Q30 improvements and confirm the cut_mean_quality 15 sliding window was applied
- phiX174 mapping reads are reduced to near zero in the cleaned FASTQ (verify via the contaminant-removal step's log) unless --keep_phix was set
- Cleaned reads assemble with MEGAHIT without contaminant-derived scaffolds dominating the assembly
- Downstream vOTU counts (e.g., 14,274 on the Liang et al. 2020 shotgun dataset with 4,666 vOTUs of >10 ORFs) are reproducible, indicating QC did not distort the viral signal
- Paired-end read counts remain synchronized between R1 and R2 output FASTQ files

## Limitations

- Users are urged to be mindful of biases inherent to virome analyses; the --virome option's nonviral-scaffold removal trades sensitivity for specificity
- The default minimum viral consensus scaffold length is 1000 bp (--minlen), but the validation workflow used --minlen 3000; differing settings change which contigs survive after dereplication
- Quality trimming thresholds and contaminant choices are defaults tuned for the MetaPhage pipeline and may need adjustment for other library types
