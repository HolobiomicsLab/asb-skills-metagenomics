# nextflow-pipeline-orchestration

## Summary

Orchestrate end-to-end population genomic analyses (filtering/basic statistics, genetic structure, TreeMix phylogeny, signatures of selection) as a single Nextflow DSL2 pipeline run (scalepopgen), with containerized dependencies and consolidated reporting via MultiQC.

## When to use

Use when biallelic SNP data in VCF or PLINK binary format must be run through a full population-genomics workflow (filtering, PCA/ADMIXTURE, TreeMix, selection scans) reproducibly on a local machine or HPC cluster via Nextflow.

## When NOT to use

- The task involves transcriptomic data — nf-core/rnaseq is a separate pipeline and scalepopgen only accepts biallelic SNP data in VCF or PLINK binary format
- VCF inputs are not split by chromosome and tabix-indexed, or chromosome names contain punctuation marks, violating the documented input sheet requirements
- Only a single analysis (e.g. one ADMIXTURE run) is needed without workflow management — running the full orchestrated pipeline adds unnecessary dependency resolution overhead

## Inputs

- Chromosome-split, tabix-indexed VCF files listed in a comma-separated input sheet (vcf_input.csv with header 'chrom,vcf,vcf_idx')
- PLINK binary files (bed/bim/fam) listed in a '.p.csv' sheet with header 'prefix,bed,bim,fam'
- Tab-delimited two-column sample map file (individual IDs and population IDs, no header, '.map' extension)
- YAML parameters file generated by the scalepopgen CLI

## Outputs

- Analysis results for the four sub-workflows (filtering/basic statistics, PCA, ADMIXTURE with Q-matrices, IBS/FST, TreeMix phylogeny, selection-scan statistics)
- Interactive Plotly/Bokeh visualizations produced by embedded Python/R collection scripts
- Final consolidated MultiQC (v1.19) HTML report including per-process computational resource usage
- Nextflow execution/trace artifacts documenting successful completion of all sub-workflows
- citation_ folder with BibTeX references generated by the CLI

## How to apply

Clone the scalepopgen repository and install only three dependencies: Nextflow, Java, and one container/environment system (conda, mamba, singularity, or docker — mamba is recommended); Nextflow automatically downloads the remaining analysis tools. Prepare inputs as chromosome-split, tabix-indexed VCFs listed in a comma-separated sheet (vcf_input.csv with header chrom,vcf,vcf_idx) or PLINK bed/bim/fam prefixes (plink_input.csv), plus a tab-delimited two-column sample map ending in '.map'. Build the YAML parameters file with the scalepopgen CLI (python scalepopgen_cli.py), which validates formats and generates a citation_ folder with BibTeX references. Launch with 'nextflow run scalepopgen/ -profile <docker/singularity/conda/mamba> -params-file <parameters.yml> -qs <max processes>'; validate the setup first with the bundled small dataset via '-profile test,<container>' and reproduce paper results with '-profile test_full,<container>'. The main script dispatches the four sub-workflows in order (sample-then-site filtering and summary statistics, genetic structure with PCA/ADMIXTURE CV-error-based K selection, TreeMix with OptM migration-edge summary, selection scans including Tajima's D, Pi, FST, SweepFinder2, iHS/XP-EHH), and embedded Python/R scripts collect results into interactive Plotly/Bokeh visualizations, with MultiQC (v1.19) compiling a final HTML report documenting per-process resource usage. In the paper's full run the pipeline finished in ~1.5 h, equivalent to ~136 CPU hours.

## Examples

```
nextflow run scalepopgen/ -profile test,<docker/singularity/conda/mamba> -qs 10
```

## Evaluation signals

- The pipeline run completes without error and the Nextflow execution report confirms all four sub-workflows (filtering/basic statistics, genetic structure, TreeMix phylogeny, signatures of selection) executed successfully
- A final MultiQC (v1.19) HTML report is emitted, compiling visualization of each analysis and per-process resource usage
- The ADMIXTURE sub-workflow emits cross-validation (CV) error values used to select a suitable K, and Q-matrices are plotted (e.g. via pong/pophelper)
- Running '-profile test,<container>' on the bundled small dataset succeeds before running actual data; '-profile test_full,<container>' reproduces the paper's results
- The CLI-generated citation_ folder contains the relevant BibTeX references for all tools invoked

## Limitations

- Users must pre-install Nextflow, Java, and one container/environment system; only Linux operating systems are supported, and mamba is the recommended environment system
- VCF inputs must be split by chromosome and indexed with tabix, and chromosome names must not contain punctuation marks
- Custom config files (including via '-c') cannot be used to override parameters — parameters must come from the '-params-file' YAML
- The test_full profile reproduces paper-scale results only for the described cattle dataset context; scaling behavior depends on available CPU hours (~136 CPU hours for the full run)
