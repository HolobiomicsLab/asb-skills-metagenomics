# norta-count-table-generation

## Summary

Generate synthetic 16S-style abundance tables with the NorTA simulator, fit to the amgut1.filt example data shipped with SPIEC-EASI, so that inferred co-occurrence networks can be scored against a known ground-truth interaction network when benchmarking MiCoNE consensus methods.

## When to use

Use when you need ground-truth synthetic abundance tables to evaluate network inference or consensus (scaled_sum) precision/sensitivity, as in the MiCoNE NorTA and seqtime benchmarks.

## When NOT to use

- You have real experimental 16S abundance data and no ground-truth network is needed — benchmark scoring against NorTA ground truth is meaningless there
- The target is evaluating the sequence-processing (SP) steps of the MiCoNE pipeline from raw reads; this skill starts from an abundance table, not FASTQ data
- A different simulator is prescribed (e.g. seqtime gLV/Klemm-Eguiluz dynamics) and only one simulator's ground truth is required

## Inputs

- amgut1.filt example abundance table shipped with SPIEC-EASI (fit target for NorTA)
- Ground-truth interaction network emitted by the NorTA simulator
- MiCoNE NI default settings (1000 bootstraps, interaction_threshold = 0.3, pvalue_threshold = 0.05) for downstream scoring

## Outputs

- Synthetic abundance count table generated by NorTA
- Ground-truth interaction network for the synthetic table
- Precision/sensitivity values against inferred networks (e.g. precision = 1.000 at theta = 1.000; 0.956 at theta = 0.333)

## How to apply

Fit the NorTA model to the amgut1.filt example abundance data distributed with SPIEC-EASI, recording the ground-truth interaction network NorTA uses to generate the counts. Produce a synthetic abundance table in the same table format the MiCoNE Network Inference (NI) step consumes. Generate the companion seqtime-based tables (generalized Lotka-Volterra and Klemm-Eguiluz dynamics) in parallel if a two-simulator comparison is required. Run inference with MiCoNE defaults (1000 bootstrap resamples, interaction_threshold = 0.3, pvalue_threshold = 0.05) and score precision/sensitivity of inferred edges against the recorded NorTA ground truth, e.g. precision = 1.000 for scaled_sum consensus at theta = 1.000 and 0.956 at theta = 0.333. Use the segrelab/MiCoNE-synthetic-data repository, which provides the synthetic data and generation scripts from the manuscript, as the reference implementation.

## Related tools

- **MiCoNE** (Python package whose Network Inference and consensus steps consume the NorTA synthetic tables and are scored against the ground truth) — https://github.com/segrelab/MiCoNE
- **spieceasi** (source of the amgut1.filt example data to which NorTA is fit)
- **MiCoNE-synthetic-data** (repository with the synthetic data and generation scripts for the MiCoNE manuscript, including NorTA-based tables) — https://github.com/segrelab/MiCoNE-synthetic-data

## Evaluation signals

- The synthetic table's inferred network (MiCoNE NI defaults: 1000 bootstraps, interaction_threshold = 0.3, pvalue_threshold = 0.05) can be compared edge-by-edge to the recorded NorTA ground truth
- scaled_sum consensus on the NorTA table reaches precision = 1.000 at theta = 1.000, matching the reported Fig. 5 value
- scaled_sum consensus at the default theta = 0.333 gives precision = 0.956 on NorTA data without significant sensitivity loss
- Generated tables reproduce the abundance structure of the amgut1.filt fit target (same taxa, comparable count distributions)
- Results should be tabulated per simulator (NorTA and seqtime) and per theta into precision_sensitivity_table.csv

## Limitations

- Precision at default theta = 0.333 differs by simulator (0.956 with NorTA vs 0.688 with seqtime), so NorTA-based benchmarking alone may overestimate consensus performance
- The MiCoNE pipeline data directory must be manually downloaded from Zenodo record 7051556 before running workflows
- Consensus precision depends on sweeping the theta parameter; a single theta setting may not reveal sensitivity loss
