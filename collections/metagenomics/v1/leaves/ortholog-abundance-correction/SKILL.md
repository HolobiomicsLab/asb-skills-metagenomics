# ortholog-abundance-correction

## Summary

MetaLAFFA's default orthology-group abundance correction step: KO-level counts (already fractionally counted and gene-length-normalized) are converted by MUSiCC into average copy number per genome per sample, instead of being left as raw read-count relative abundances.

## When to use

Use when a KO-level abundance table from shotgun metagenomic read mapping needs normalization before pathway aggregation, and per-genome copy-number values (not raw relative abundances) are required.

## When NOT to use

- The user explicitly wants simple relative abundances of KOs — in that case switch the 'method' parameter to 'relative' instead of using the MUSiCC default.
- Input is not a KO-level ortholog abundance table from shotgun metagenomic read mapping (e.g. it is a pathway-level table already aggregated from corrected KOs).
- Working on Windows — MetaLAFFA, which hosts this step, is only supported on Mac and Linux.

## Inputs

- KO abundance table generated by the ortholog counting step (fractionally counted, gene-length-normalized read counts per sample)
- Configuration file config/steps/ortholog_abundance_correction.py defining the correction method and parameters

## Outputs

- MUSiCC-corrected KO abundance table (average KO copy number per genome per sample) as a tab-separated values file, KOs as rows and samples as columns

## How to apply

Load the KO abundance table produced by the ortholog counting step, whose gene abundances have already been fractionally counted for multi-matches and normalized by gene length via MetaLAFFA's custom Python script. Invoke the ortholog abundance correction step implemented in config/steps/ortholog_abundance_correction.py, keeping the 'method' parameter at its default MUSiCC (Manor and Borenstein 2015) rather than switching it to 'relative'. MUSiCC then performs inter-sample normalization with intra-sample correction using learned models, anchored on universally single-copy bacterial genes as the normalization basis. Write the corrected table — average KO copy number per genome per sample — to disk as a tab-separated values file for downstream aggregation of orthology groups into higher-level functional descriptions (e.g. KEGG modules and pathways).

## Evaluation signals

- The output TSV file exists and is parseable as a tab-delimited table with KOs as rows and samples as columns.
- Cell values represent MUSiCC-corrected average KO copy numbers per genome, not raw read-count relative abundances (e.g. values need not sum to 1 per sample).
- The 'method' parameter in config/steps/ortholog_abundance_correction.py was left at its default (MUSiCC), not set to 'relative'.
- Corrected values are consistent with MUSiCC's inter-sample normalization plus intra-sample correction using universally single-copy bacterial genes.
- The step completes without the known 'undefined symbol: omp_get_num_procs' runtime error reported in the MetaLAFFA FAQ.

## Limitations

- Known environment issue: running MUSiCC can fail with the error 'undefined symbol: omp_get_num_procs', which requires a fix described in the MetaLAFFA FAQ.
- The step is part of MetaLAFFA, which is supported on Mac and Linux but not on Windows.
- MUSiCC normalization relies on universally single-copy bacterial genes, so correction quality depends on the community containing enough of these marker genes.
