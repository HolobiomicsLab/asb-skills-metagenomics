# physical-coverage-parameter-optimization

## Summary

Optimizes 10x Linked-Read library parameters — especially physical coverage of long DNA fragments (CF) versus short-read coverage per fragment (CR) at constant total coverage C = CR × CF — to maximize de novo diploid assembly contiguity. The article found contig contiguity decreases as CF rises, with an optimal CF window of 332×–823× and degradation above 1,000× at the recommended C = 56×.

## When to use

Use when designing or simulating 10x Chromium Linked-Read libraries and you must choose CF, CR, or fragment length (Mu_F) at a fixed total coverage C to maximize contig N50 of a Supernova2 diploid assembly.

## When NOT to use

- You are using an assembler other than Supernova2 — the fragment-length and CF effects are implementation-specific ('until there is another assembler that can be compared to Supernova2 it will not be possible to reason about this effect').
- Total coverage C is not held constant across the libraries being compared — varying CF and C simultaneously confounds the physical-coverage effect the skill isolates.
- The technology is not barcode-based linked reads (e.g. PacBio/ONT long reads); the CF/CR decomposition is specific to 10x Chromium-style partitioned libraries.

## Inputs

- Diploid reference FASTA pair generated by gen_fasta.py from an hg38 reference and a VCF of SNVs (e.g. sample.vcf, ref.fasta)
- LRTK-SIM configuration files specifying CF, CR, N_FP, Mu_F, SR, Error_rate, Mu_IS, Std_IS, processors, and Hap=2
- Optional: real 10x Linked-Read FASTQ libraries from cell lines such as NA12878/NA24385 with known library parameters for cross-checking simulation trends

## Outputs

- Paired-end gzipped FASTQ files per simulated library (X_S1_L001_R1_001.fastq.gz and X_S1_L001_R2_001.fastq.gz) in lib_X folders
- Supernova2 de novo diploid assemblies per simulated library
- Table of contig N50 (and NA50 accuracy) versus CF, CR, and fragment length (Mu_F/W_mu_FL) identifying the optimal CF window (332×–823×) and W_mu_FL (~50–150 kb)

## How to apply

Generate two haploid diploid reference FASTAs by inserting SNVs from a VCF into hg38 with gen_fasta.py, then write LRTK-SIM configuration files that hold total coverage constant (e.g. C = 56×) while varying CF (line7) at fixed CR (line9) and vice versa, also setting Mu_F, SR, Error_rate, Mu_IS, Std_IS, and Hap=2 (line33). Run 'python LRTK-SIM.py <path to configuration files>' to simulate all libraries in parallel, producing paired-end gzipped FASTQs per library, then assemble each with Supernova2 and tabulate contig N50 (and NA50 accuracy) against CF and length-weighted fragment length (W_mu_FL). The article's decision points are: keep CF between ~332× and 823×, avoid CF > 1,000× at C = 56×, and target a W_mu_FL of ~50–150 kb, since longer fragments extended phase blocks but reduced contig contiguity. Validate by confirming contig N50 decreases monotonically as CF (or fragment length) increases beyond the optimal window at constant C.

## Evaluation signals

- Contig N50 must decrease as CF increases beyond ~823× at constant C = 56×, with quality worsening above 1,000×.
- The measured optimal CF window should fall between 332× and 823× for the recommended total coverage C = 56×.
- The optimal length-weighted fragment length (W_mu_FL) should land in the ~50–150 kb range; including more extremely long fragments should degrade assembly quality.
- At broadly optimal parameters, ~80% of the genome should assemble in a diploid state.
- Simulated trends should be confirmed against real libraries (e.g. NA12878/NA24385) at C = 56×, and total-coverage sweeps should show contig N50 rising from ~621.4 to 758.1 kb beyond 56×.

## Limitations

- The detrimental effect of extremely long fragments is only a proposed explanation (loss of barcode specificity for fragments spanning repetitive sequences), not verified.
- No alternative assembler to Supernova2 was available for comparison, limiting generalization of the CF and fragment-length effects.
- 10x Chromium amplification captures only ~20–40% of the original long fragment sequence per partition, which constrains achievable CF in practice.
- gen_fasta.py supports only SNVs for constructing the diploid reference; structural variants are not modeled in simulation.
