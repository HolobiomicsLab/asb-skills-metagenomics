# plink-binary-genotype-processing

## Summary

Prepare biallelic SNP genotype data in PLINK binary (BED/BIM/FAM) format for downstream scalepopgen analyses, including VCF-to-BED conversion with plink, chromosome-ID recoding to integers, and LD pruning with user-defined PLINK2 parameters before structure analyses such as smartpca and ADMIXTURE.

## When to use

Use when input genotype data are VCF or PLINK binary files that must be converted to PLINK BED format, chromosome IDs recoded to integers, and LD-pruned before PCA, ADMIXTURE, TreeMix, or selection-scan analyses.

## When NOT to use

- Data are not biallelic SNPs — scalepopgen is built for biallelic SNP data in VCF or PLINK binary format, so multi-allelic variants or haplotypes fall outside its scope
- The analysis at hand requires unpruned SNP density (e.g. signature-of-selection statistics that need full SNP sets rather than the LD-pruned subset recommended before structure analyses)
- The input needs extensive sample/site filtering first — those belong to the separate 'filtering and basic statistics' sub-workflow, not this genotype-processing step

## Inputs

- Chromosome-split, tabix-indexed VCF files listed in a vcf_input.csv sheet (header: chrom,vcf,vcf_idx)
- PLINK binary files (bed/bim/fam) listed in a .p.csv sheet (header: prefix,bed,bim,fam)
- Tab-delimited sample map (.map) of individual IDs and population IDs without header
- YAML parameters file generated by the scalepopgen CLI

## Outputs

- PLINK binary (BED/BIM/FAM) genotype files with integer chromosome IDs
- LD-pruned PLINK binary SNP set used as input to smartpca and ADMIXTURE analyses

## How to apply

Split VCF inputs by chromosome, index them with tabix, and list them in a comma-separated input sheet (header 'chrom,vcf,vcf_idx') where chromosome names must not contain punctuation marks; alternatively point to existing PLINK binary files via a '.p.csv' sheet with header 'prefix,bed,bim,fam'. Convert VCF to binary PED (BED) format with plink, recoding non-integer chromosome IDs to integers (e.g. with PLINK) so tools expecting integer chromosome IDs can read the data. Then apply recommended LD-based filtering using user-defined PLINK2 LD pruning parameters before supplying the input file to the respective analysis (e.g. smartpca from Eigensoft or ADMIXTURE over a range of K values). In the scalepopgen case study, this reduced ∼25 million SNPs in 442 cattle samples to 129,357 SNPs after LD pruning.

## Evaluation signals

- VCF input sheets use the exact header 'chrom,vcf,vcf_idx' and PLINK sheets use 'prefix,bed,bim,fam'; chromosome names contain no punctuation marks
- The sample map has exactly two tab-delimited columns (individual ID, population ID), no header line, and a '.map' file extension
- BIM file chromosome IDs are integers after recoding, so tools expecting integer chromosome IDs (smartpca, ADMIXTURE) read the data without errors
- LD pruning applies the user-defined PLINK2 LD parameters and yields a plausible SNP reduction (case study: ∼23.4 million SNPs pruned to 129,357)
- Downstream runs succeed: smartpca produces PCs and ADMIXTURE logs contain a CV-error value for every tested K over the LD-pruned BED input

## Limitations

- Chromosome names must not contain punctuation marks, which may force renaming before VCF input is accepted
- LD pruning is only 'recommended', not mandatory — omitting it leaves genome-scale SNP density that can inflate runtime and violate assumptions of structure tools
- PLINK binary input must already be split into bed/bim/fam triplets referenced in the .p.csv sheet; the pipeline does not accept a single monolithic VCF
