# population-allele-frequency-summary-statistics

## Summary

Implements the 'filtering and basic statistics' sub-workflow of scalepopgen: sample- then site-filtering of biallelic SNP genotype data (VCF or PLINK BED) with PLINK v1.9, PLINK2, and Vcftools v0.1.16, followed by computation of individual- and population-level allele-frequency summary statistics such as MAF, observed and expected heterozygosity, and transition/transversion counts.

## When to use

Use when you have chromosome-split, tabix-indexed biallelic VCF files (or PLINK BED/BIM/FAM) plus a sample-to-population map and need QC filtering plus per-sample and per-window population statistics (MAF, Ho, He) before downstream population-genomic analyses.

## When NOT to use

- The input is already a filtered PLINK binary dataset with per-population statistics computed — re-running sample filtering first would only remove additional samples
- The data are multiallelic variants, indels, or whole-genome haplotypes rather than biallelic SNP VCF/PLINK files, which the scalepopgen sub-workflows do not accept
- The goal is structural analyses (PCA, ADMIXTURE, TreeMix phylogeny, selection scans) rather than filtering and basic summary statistics

## Inputs

- CSV input sheet listing chromosome-split, tabix-indexed VCF files (vcf_input.csv with chrom,vcf,vcf_idx header)
- PLINK binary files (BED/BIM/FAM) listed in a .p.csv sheet
- Sample map file (.map) with two tab-delimited columns: individual ID and population ID, no header
- YAML parameter file specifying filtering and statistics options (generated by the scalepopgen CLI)

## Outputs

- Filtered PLINK binary (BED) genotype files
- Per-individual summary statistics (heterozygous, homozygous-reference, homozygous-alternative SNP counts, transitions, transversions)
- Per-population, per-window summary statistics (average MAF, observed heterozygosity, expected heterozygosity)
- Summary tables compiled by the workflow's custom Python scripts

## How to apply

Load the CSV input sheet of chromosome-split VCFs (or PLINK BED files) and the two-column sample map file, with all parameters read from a YAML configuration file generated by the scalepopgen CLI. Apply sample-level filtering first (e.g. genotype missingness) using Plink v1.9, Plink2, and Vcftools v0.1.16, then apply site-level filtering (e.g. MAF), since the workflow mandates that site filtering is carried out after sample filtering. Optionally prune sites by linkage disequilibrium with user-defined Plink2 LD parameters before supplying the input to downstream analyses, and convert the filtered data to PLINK binary (BED) format. Compute individual-based statistics (counts of heterozygous, homozygous-reference, and homozygous-alternate SNPs, transitions, and transversions) and population-based statistics in user-defined windows (average MAF, observed and expected heterozygosity). Compile the statistics with the custom Python scripts supplied with the workflow into summary tables for inspection and visualization. In the paper's cattle case study (Animal_SNPAtlas, 442 samples, 30 breeds), filtering reduced the set to 269 samples (17 breeds) and ~23.4 million SNPs, and LD pruning reduced it further to 129,357 SNPs.

## Examples

```
nextflow run scalepopgen/ -profile docker -params-file filtering_stats.yml -qs 10
```

## Evaluation signals

- The filtered dataset must be strictly smaller than the input in both sample count and site count (in the case study: 442 samples/~25 million SNPs reduced to 269 samples/17 breeds and ~23.4 million SNPs)
- Site filtering must occur after sample filtering — verify the mandated filter order in the process logs
- If LD pruning was requested, the pruned site count should be substantially lower than the post-filter site count (case study: 129,357 SNPs after LD-based filtering)
- Summary tables must contain both per-individual counts (het, hom-ref, hom-alt, transitions, transversions) and per-window population metrics (MAF, Ho, He)
- Transition/transversion counts per individual should be internally consistent with the SNP counts in the filtered BED files

## Limitations

- Only biallelic SNP data in VCF or PLINK binary format are supported; the pipeline was designed for such inputs and the case study used phased, imputed autosomal SNP genotypes
- VCF inputs must be split by chromosome, indexed with tabix, and chromosome names must not contain punctuation marks
- Filter thresholds are user-defined, so results (e.g. breed/sample retention) depend strongly on parameter choices; the case study lost 173 of 442 samples and 15 of 30 breeds under the reported parameters
