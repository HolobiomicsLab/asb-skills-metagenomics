# protein-contact-prediction-inference

## Summary

Run the DeepECA pre-trained multitask DNN to predict residue-residue contacts and secondary structures directly from a protein's MSA, producing contact probability maps in ./contact_pred and ./ss_pred without retraining.

## When to use

Use when you have an amino acid sequence (or FASTA) plus a generated MSA and need predicted contact residues and secondary structures from DeepECA's pre-trained models, e.g. as inputs to CONFOLD structure building.

## When NOT to use

- You want to train new models rather than run inference — use the training path (multitask.py, 2–3 days on an NVIDIA TITAN GTX GPU) instead
- Your goal is precision-matrix-based ECA comparison (e.g. CCMpred/PSICOV timings or baselines) rather than DNN-based end-to-end prediction
- Proteins exceed 700 residues or are shorter than 25 residues, which the paper's data preparation explicitly excludes

## Inputs

- Amino acid sequence FASTA files placed in ./dataset/fasta
- Pre-trained DeepECA models (Google Drive folder linked in README)
- Multiple sequence alignments generated by HHblits (three iterations, E-value 0.001, coverage 60%)

## Outputs

- Contact predictions stored in ./contact_pred (contact probability per residue pair, Cβ/Cα distance < 8 Å definition)
- Secondary-structure predictions stored in ./ss_pred
- Optionally tertiary structures from top 2L contacts via CONFOLD, evaluated by TMscore

## How to apply

Download the pre-trained models from the authors' Google Drive folder and place them per the repo layout, then ensure Python3, numpy, pandas, TensorFlow r1.11.0, and HHblits are installed (tested on Ubuntu 16.04). Set up MSA generation by editing the HHblits path in run_hhblits_local.py; MSAs elsewhere in the paper were built with three HHblits iterations, E-value 0.001, and 60% coverage against UniProt20_2016. Put your FASTA files into ./dataset/fasta and run `python pipeline.py`, which uses the multitask model and writes contact predictions to ./contact_pred and secondary-structure predictions to ./ss_pred. Contacts are defined as Cβ (Cα for glycine) atom pairs within 8 Å; for downstream structure building feed up to the top 2L contacts to a CONFOLD script and score with TMscore. For wall-clock comparisons on the 150-protein PSICOV dataset, time the pipeline with an NVIDIA TITAN GTX GPU and again restricted to CPU.

## Related tools

- **DeepECA** (Pre-trained multitask DNN executed via pipeline.py to predict contacts and secondary structures from the MSA) — https://github.com/tomiilab/DeepECA
- **HHblits** (Generates the MSA input for prediction; path must be edited in run_hhblits_local.py)
- **CONFOLD** (Builds tertiary structures from up to the top 2L predicted contacts for downstream TMscore evaluation)

## Examples

```
python pipeline.py
```

## Evaluation signals

- Both output directories ./contact_pred and ./ss_pred are populated after pipeline.py completes
- On the 150-protein PSICOV dataset, inference wall-clock time is on the order of minutes (10 min CPU, 2 min GPU), far below CCMpred's 58 min CPU / 5 min GPU
- Contact predictions follow the 8 Å Cβ (Cα for glycine) distance definition used for evaluation
- Top 2L contacts fed to CONFOLD yield TMscore > 0.5 for a majority of CASP11-style domains (48% in the paper) when structures are built
- Model comparisons against meta-predictors show accuracy equivalent to or better than existing methods on past CASP target domains

## Limitations

- Runs on TensorFlow r1.11.0 and was tested only on Ubuntu 16.04; environment drift may break the pipeline
- GPU memory limited the network depth to 60 layers, constraining model capacity
- Mirror image-like tertiary structure failures (e.g. T0845-D1) occur when contact information is insufficiently precise
- Pre-trained models and datasets must be downloaded from a Google Drive link; RaptorX-Contact comparisons relied on a web server, so external server dependencies may be unavailable
