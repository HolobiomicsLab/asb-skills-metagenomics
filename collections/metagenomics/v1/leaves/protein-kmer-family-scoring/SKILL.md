# protein-kmer-family-scoring

## Summary

Reconstructs Snekmer's supervised kmer scoring scheme: family probability F_kmer = n_kmer/N, a modified family probability F'_kmer that penalizes kmers shared with other families, and the overall score S_kmer combining F'_kmer with background kmer prevalence P_kmer to yield values strictly within (-1, 1).

## When to use

Use when implementing or reproducing supervised kmer-based protein family scoring from reduced-alphabet (AAR) kmer count matrices, needing family-specific kmer weights that penalize kmers present in out-group families.

## When NOT to use

- Unsupervised clustering of sequences (Snekmer's 'cluster' mode) is the goal — no family labels exist to compute F_kmer against
- Input is already a trained supervised model or a scored results table (e.g. results/apply/snekmer_results.csv) — scoring has already been performed
- Sequences have not yet been recoded into AAR kmer vectors — run Snekmer's encoding/kmerization step first

## Inputs

- Reduced-alphabet (AAR) kmer count/binary presence matrix per protein sequence, generated by Snekmer's encoding
- Family/annotation labels mapping sequences to protein families (e.g. TIGRFAMs_annotation.ann)
- Number of families G and per-family sequence counts N

## Outputs

- Per-kmer family probability scores F_kmer = n_kmer/N
- Per-kmer modified family probability scores F'_kmer (out-group penalized)
- Overall kmer scores S_kmer in the open interval (-1, 1)
- Unit-test results validating boundary semantics against hand-computed fixtures

## How to apply

First define the family probability F_kmer as the fraction n_kmer/N of sequences within a family that contain a given AAR-kmer, computing counts from reduced-alphabet kmer vectors produced by Snekmer's encoding. Then compute the modified family probability F'_kmer by subtracting, from F_kmer, the summed fractional probabilities of the same kmer in every other family, so that kmers shared across families are penalized. Finally compute the overall score S_kmer by combining F'_kmer with the background prevalence P_kmer of the kmer across the dataset; the result must fall in the open interval (-1, 1), where 1 means the kmer occurs in all in-group and no out-group sequences, -1 the reverse, and 0 denotes in-group/out-group agnosticism. Unit-test each formula against hand-computed fixtures, including edge cases such as kmers unique to one family and kmers present in all families, and smoke-test end-to-end with the demo annotation file TIGRFAMs_annotation.ann and a small kmer count matrix.

```
snekmer apply --ann resources/demo_sequences/learn_apply_inputs/annotations/TIGRFAMs_annotation.ann
```

## Evaluation signals

- Every computed S_kmer is strictly within the open interval (-1, 1)
- A kmer present in all in-group and no out-group sequences scores approaching +1; the reverse approaches -1; in-group/out-group agnostic kmers score 0
- Kmers present in all families receive penalized (near-zero or negative) F'_kmer scores after out-group subtraction
- Unit tests pass against hand-computed fixtures including unique-kmer and ubiquitous-kmer edge cases
- Smoke test on TIGRFAMs_annotation.ann plus a small kmer count matrix parses inputs and reproduces expected scores end-to-end

## Limitations

- Representing proteins as kmer sets uses an exact-match methodology that may be limited in sensitivity and coverage; AAR mitigates but does not remove this
- Scores are only interpretable relative to the families in the training set; background prevalence P_kmer depends on the dataset composition
- Boundary values (-1 and 1) are limits approached, not necessarily attained, so validation must check strict openness of the interval
