# protein-msa-sequence-weighting

## Summary

Learn per-sequence weights of a deep multiple sequence alignment end-to-end inside a DNN (DeepECA's Weighted MSA Model) so noisy sequences are automatically down-weighted, boosting protein contact prediction accuracy over an unweighted baseline.

## When to use

Use when the goal is protein contact prediction from an MSA and MSA noise (e.g., metagenomic or noisy HHblits hits) may be degrading accuracy, and you want supervised, learned sequence weighting instead of fixed PSICOV-style weights.

## When NOT to use

- When a high-quality, noise-free MSA is already available and a simpler unweighted baseline suffices — weighting helps most when MSA noise or shallow MSAs are a concern
- When a local execution of the comparison method is required and only a web server exists (e.g., RaptorX-Contact had no local execution file available)
- When the input is not an MSA (e.g., a covariance or precision matrix from another tool such as DeepCov or ResPRE is already the input feature)

## Inputs

- Amino-acid FASTA files for target proteins (placed in ./dataset/fasta for custom targets)
- MSAs generated by HHblits (three iterations, E-value 0.001, coverage 60% on the UniProt20_2016 library)
- Pre-trained models and training datasets from the Google Drive folder (1_Ys7dZ2P0uF52nvXZkkMeIv0rbqhUMPj)
- Contact ground truth for evaluation: residue pairs with Cβ–Cβ distance < 8 Å (Cα for glycine)

## Outputs

- Per-sequence MSA weight distributions learned by the MLP weighting module (visualizable to show down-weighting of noisy sequences)
- Residue-pair contact probabilities stored in ./contact_pred
- Predicted secondary structures and solvent accessibility stored in ./ss_pred (multitask model)
- Contact prediction accuracy at each distance bin and prediction count (e.g., Table 2/Table 3 comparisons)

## How to apply

Download the pre-trained models and training datasets from the Google Drive folder linked in the methods, and set up HHblits by editing the HHblits path in run_hhblits_local.py. Train the Weighted MSA Model with the multitask script using the ADAM optimizer at learning rate 0.0005, batch normalization, and one domain per batch, cropping 200 residues per protein and sampling up to 30,000 MSA sequences (about 2-3 days on an NVIDIA TITAN GTX GPU). Run contact prediction with the multitask model (pipeline.py), storing outputs in ./contact_pred (and ./ss_pred for secondary structure), where contacts are defined as Cβ atoms within 8 Å (Cα for glycine). To judge success, evaluate contact prediction accuracy at each distance bin and prediction count and confirm the Weighted MSA Model beats the unweighted Baseline at every setting, is equivalent-or-better than the Baseline with PSICOV sequence weighting, and that dropping the consensus-identity feature gives the lowest accuracy among feature variants.

## Related tools

- **DeepECA** (The end-to-end DNN framework whose Weighted MSA Model learns per-sequence MSA weights and predicts contacts from the MSA directly) — https://github.com/tomiilab/DeepECA

## Evaluation signals

- Weighted MSA Model achieves higher contact prediction accuracy than the Baseline Model at every distance bin and prediction count (Table 2)
- Learned weighting is equivalent-or-better than the Baseline using PSICOV sequence weighting (Table 3b)
- Feature ablation: removing the consensus-identity feature yields the lowest accuracy among feature variants (Table 3a)
- Accuracy is retained on noisy HHblits MSAs generated with E-values 1 and 3 and the '-cov' option removed (Table 1), showing automatic noise reduction
- Training run completes in the expected ~2-3 days on an NVIDIA TITAN GTX GPU with the specified ADAM learning rate 0.0005

## Limitations

- Training is computationally heavy (~2-3 days on an NVIDIA TITAN GTX GPU) and network depth was capped at 60 layers due to GPU memory limitations
- When the number of sequences exceeds 30,000, only 30,000 are sampled and only 200 residues are cropped per protein during training
- RaptorX-Contact comparisons are missing for 3 of 105 CASP11 domains and 1 of 55 CASP12 domains because predictions had to be computed on a web server (server errors)
- Improving MSA construction and gathering sufficient evolutionary information for shallow MSAs is left as future work; sequence/MSA-derived features only partially mitigate shallow-MSA accuracy
