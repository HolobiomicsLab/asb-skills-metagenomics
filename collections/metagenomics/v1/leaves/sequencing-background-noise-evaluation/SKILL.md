# sequencing-background-noise-evaluation

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Measures background noise and limit of detection (LoD) for hotspot mutation calls generated by the Nano2NGS-Muta nanopore-to-NGS conversion framework. Because the framework performs no error correction and different NGS analysis algorithms produce different result features, noise must be empirically characterized on actual data.

## When to use

Use when hotspot mutation calls from converted nanopore short reads must be qualified by an empirically measured background noise profile and LoD before being trusted for clinical hotspot panels.

## When NOT to use

- Input is genuine NGS short-read data with random error profiles — the conversion step's non-random nanopore noise is absent, so this noise evaluation is unnecessary
- Data are destined for Nano2NGS-Meta metagenomic taxonomic classification rather than hotspot mutation detection
- A validated LoD and background noise profile already exist for the exact same algorithm, pipeline, and platform-matched data

## Inputs

- Nanopore sequencing FASTQ / fq.gz reads (long reads)
- Hotspot BED configure file (chr, start, end, gene symbol, mutation, optional transcription ID)
- check-hotspot.list file containing ALL mutation positions
- Per-dataset hotspot mutation detection results from the NGS analysis pipeline applied to each NGS-liked short-read set

## Outputs

- Background noise profile for the specific analysis algorithm and sequencing platform
- Limit of detection (LoD) estimate: the mutation-frequency threshold balancing false positive and false negative rates
- Final hotspot mutation calls written to hotspot_mutation_calls.txt, qualified by the measured noise

## How to apply

First convert nanopore FASTQ long reads into NGS-liked short-read sets with nano2ngs-muta.pl (e.g. -read_len 101, -position_step 10), apply the chosen NGS mutation pipeline (e.g. GATK Best Practice) to each set, and integrate per-set calls with position-based weights summing to 1 against check-hotspot.list. Then run background noise evaluation on actual experimental data from the same sequencing platform: the README states that different analysis algorithms produce different result features, so the noise profile and mutation-frequency threshold must be re-derived for each algorithm/pipeline combination rather than reused. Set the LoD as the mutation-frequency threshold at which the false positive rate and false negative rate are best controlled; do not substitute simulated ONT/ONT-like data, since the article notes such simulations were not generated on the same experimental platform. Report which algorithm versions and training datasets were used, because the authors found default published training datasets may be inappropriate for their experimental data.

## Examples

```
perl nano2ngs-muta.pl -fq nanopore.fq -read_len 101 -position_step 10 -configure Hotspot.bed -process 8
```

## Evaluation signals

- Background noise is measured on actual experimental nanopore data from the same platform, not on simulated ONT/ONT-like data
- The reported LoD is expressed as a mutation-frequency threshold tied to controlled false positive and false negative rates
- Every final target hotspot mutation call is checked against the complete check-hotspot.list
- The integration weights over the N short-read sets sum to 1, with results not detected across extracted datasets filtered out
- Converted reads' residual error rates are documented, since Nano2NGS performs no error correction and error rates remain similar to the long reads

## Limitations

- The Nano2NGS framework performs no error correction for reads or bases, so converted short reads may contain lower or similar error rates to the long reads
- LoD is not yet established; the authors state more samples are needed to better control false positive and false negative rates at the mutation-frequency threshold
- Simulated ONT or ONT-like data were not generated on the same experimental and sequencing platforms
- The authors' experimental data were insufficient as training data for iGDA and PEPPER-Margin-DeepVariant, so default published training datasets were used and may be inappropriate
- No software version numbers were reported for the analysis tools
