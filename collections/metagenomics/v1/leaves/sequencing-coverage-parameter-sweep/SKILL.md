# sequencing-coverage-parameter-sweep

## Summary

Systematically vary 10x Linked-Read coverage parameters — total coverage C = CR × CF, physical fragment coverage (CF), read coverage per fragment (CR), and fragment length (Mu_F / WμFL) — by simulating libraries with LRTK-SIM and/or sequencing real libraries, then assembling with Supernova2 to map assembly quality onto the parameter space.

## When to use

Use when planning or evaluating 10x Chromium Linked-Read library preparation/sequencing parameters (CF, CR, C, fragment length) and you need to know which combinations maximize contig/scaffold N50 and NA50 for diploid de novo assembly.

## When NOT to use

- The goal is simulation for metagenomics with unequal species abundances without supplying the two-column abundance flat file (sequence name and abundance summing to 1) that LRTK-SIM requires
- Assemblies are from long-read (PacBio/ONT) or other barcode-based technologies (CPTv2-seq, stLRF) rather than 10x Linked-Reads, since the parameter map was derived for 10x data
- Input is a single haploid simulation where diploid phase-block and NA50 metrics from Hap=2 diploid simulation are not meaningful

## Inputs

- Two haploid reference FASTA files generated by gen_fasta.py from a reference genome and VCF (or one FASTA for haploid simulation)
- LRTK-SIM configuration files specifying CF, CR, N_FP, Mu_F, SR, Error_rate, Mu_IS, Std_IS, processors, and Hap=2
- Optional: real 10x Linked-Read fastq libraries from cell lines such as NA12878/NA24385 with varied coverage parameters

## Outputs

- Per-library folder lib_<config> containing paired gzipped fastq files X_S1_L001_R1_001.fastq.gz and X_S1_L001_R2_001.fastq.gz
- Supernova2 assemblies (megabubbles output) per simulated or real library
- Comparison of contig/scaffold N50, NA50, and phase-block metrics across the CF/CR/Mu_F sweep

## How to apply

Author one LRTK-SIM configuration file per library in a config folder (e.g. diploid_config), setting Path_Fastahap1/Path_Fastahap2 to the two haploid FASTAs generated by gen_fasta.py from the reference and a VCF (SNVs only), and sweeping CF (fragment coverage), CR (read coverage per fragment), and Mu_F (average fragment length in Kb) while fixing SR, Error_rate, Mu_IS, Std_IS, and Hap=2. Run 'python LRTK-SIM.py <config folder>' so all libraries simulate simultaneously, then assemble each output fastq pair with Supernova2 (megabubbles output) and compare contig N50, NA50, and scaffold metrics. Interpret results through the article's parameter map: keep total coverage C = CR × CF high, hold CF between ~332x and 823x (quality worsens above 1,000x for a given C), and target a length-weighted fragment length (WμFL) of ~50–150 kb; longer fragments extend phase blocks but decrease contig contiguity. For real libraries, approximate the simulated parameter combinations and, to raise C (e.g. 48x to 67x), sequence multiple 10x libraries from the same DNA preparation and merge them for analysis.

## Evaluation signals

- Each run's lib_<config> folder contains both gzipped fastq files (X_S1_L001_R1_001.fastq.gz and X_S1_L001_R2_001.fastq.gz) in 10x naming format accepted by Long Ranger and Supernova pipelines
- At fixed total coverage C, assembly quality stays stable for CF between ~332x and 823x and degrades when CF exceeds 1,000x
- Sweeping fragment length reproduces the article's trend: longer fragments (toward WμFL beyond ~50–150 kb) extend phase blocks but reduce contig contiguity
- Real-library replication shows increasing C from 48x to 67x raises scaffold N50 from 13.4 to 30.6 Mb and NA50 from 6.3 to 12.0 Mb, while scaffold accuracy falls from 46.6% to 39.1%
- With broadly optimal parameters, ~80% of the genome assembles in a diploid state

## Limitations

- The harm from extremely long fragments is only a proposed explanation (loss of barcode specificity for fragments spanning repetitive sequences), not verified
- Only ~20–40% of the original long fragment sequence is captured per 10x partition because of partition-wise amplification
- No alternative assembler to Supernova2 was available for comparison, so the fragment-length effect may be specific to Supernova2's implementation
- Scaffold accuracy can decrease even as scaffold N50 and NA50 rise with higher C
- Real 10x library sequencing involves an estimated ~2x cost increase over standard Illumina sequencing due to preparation cost and higher sequence coverage needs
