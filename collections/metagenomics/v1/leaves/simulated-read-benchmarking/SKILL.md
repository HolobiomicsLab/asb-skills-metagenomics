# Simulated-read benchmarking

## Summary

Benchmark read-classification methods by generating reads of known provenance with a long-read simulator (PBSIM2 for PacBio CLR and Nanopore) and scoring a classifier such as SPUMONI, whose positive/null matching-statistic distributions and KS-stat thresholds (0.25 for MS, 0.10 for PML) can be validated against ground truth.

## When to use

Use when evaluating a streaming read classifier against large, repetitive pan-genome indexes and you need ground-truth labels; simulated Nanopore/PacBio reads give known target vs. nontarget origins for computing accuracy and F1.

## When NOT to use

- The input is raw nanopore electrical signal — SPUMONI operates on base-called sequences and cannot use the Read Until API directly; a separate base caller must run upstream
- Target and nontarget reads share substantial sequence similarity (e.g. conserved genes between species) — the null index of reversed sequences may be insufficient for principled ejection decisions
- Ground truth is already available from real data with confident alignments — simulation adds no labeling value and the single published KS-stat threshold may not transfer to your read accuracy/reference

## Inputs

- Reference FASTA of target (and decoy/null) genome sequences, e.g. many strains per species
- Simulated Nanopore or PacBio CLR reads generated by PBSIM2 with known source loci
- Optional real base-called Nanopore FASTQ reads for threshold tuning (note: the published KS-stat threshold was optimized on real nanopore data)

## Outputs

- SPUMONI classification report file (via -c) labeling each read target/nontarget by majority-of-regions voting
- Per-region MS or PML values and KS statistics against the null-index distribution
- Accuracy/F1 comparison table versus minimap2 baseline on the same simulated reads

## How to apply

Simulate long reads whose origins are known with PBSIM2 (model-based mode, e.g. --hmm_model for Nanopore), sampling from a reference where positive and null statistic distributions differ. Build SPUMONI's positive index over target sequences plus their reverse complements, and a null index from the reverse (not reverse-complement) of those sequences, via 'spumoni build -r <reference.fa> -M -P -m -o <prefix>'. Stream reads through 'spumoni run', computing MSs (-M) or PMLs (-P) over 90 bp nonoverlapping regions; for each region subtract the null-index mean and compute the Kolmogorov-Smirnov statistic. Classify each read as target when a majority of its 90 bp regions exceed the KS-stat threshold (0.25 for MS, 0.10 for PML), writing a report with -c. Because simulation provenance is known, compute classification accuracy/F1 and compare against minimap2 run on an index with many strains per species — SPUMONI reported similar accuracy at about 12x speed.

## Examples

```
pbsim --depth 20 --hmm_model data/P6C4.model sample/sample.fasta
```

## Evaluation signals

- On simulated E. coli reads, the classification report separates target from nontarget reads by majority-of-regions voting at KS-stat thresholds 0.25 (MS) or 0.10 (PML)
- Positive-index statistic distributions are shifted to longer MSs than the null index, since longer MSs indicate a better approximate match to the index
- Measured F1/accuracy against known simulated origins is comparable to minimap2 on an index with many strains per species
- SPUMONI throughput on the benchmark is markedly higher than minimap2 (about 12x in the mock-community depletion scenario) with index/peak-memory footprints 16x/4x smaller
- Validation uses regions where positive and null statistic distributions are known to differ, confirming the hypothesis-testing framework discriminates target from random-chance matches

## Limitations

- The null index built from reversed sequences may fail when depletion-target reads and non-target reads share substantial sequence similarity (e.g. conserved genes between species)
- A single KS-stat threshold (optimized on real nanopore data) is used for all experiments; the optimal threshold depends on read accuracy and the reference, and no per-experiment thresholding method is provided
- A separate base caller must run upstream of SPUMONI; it cannot yet interact directly with the Read Until API on a nanopore sequencer
- Methods sections name no specific datasets or accessions, and SPUMONI's version number is not stated
