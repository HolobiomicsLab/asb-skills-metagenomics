# snp-genotype-quality-filtering

## Summary

The filtering and basic statistics sub-workflow of scalepopgen, which applies sample-level then site-level filtering (genotype missingness, MAF), optional LD pruning, and computes individual- and population-level summary statistics on biallelic SNP VCF or PLINK binary input.

## When to use

Use when a chromosome-split VCF or PLINK BED input needs quality filtering before population-genomic analyses, and genotype missingness, MAF, and LD-pruning criteria must be applied in a mandated order.

## When NOT to use

- Input data are not biallelic SNP genotypes (the workflow targets biallelic SNP VCF or PLINK binary files only)
- Samples and sites are already quality-filtered and only downstream structure/selection analyses are needed — use the other scalepopgen sub-workflows instead
- Chromosome names in the VCF contain punctuation marks, which the input sheet forbids — fix the naming before running

## Inputs

- CSV input sheet listing chromosome-split, tabix-indexed VCF files (.vcf.gz + .tbi) with header chrom,vcf,vcf_idx
- CSV input sheet listing PLINK binary files with header prefix,bed,bim,fam
- Tab-delimited sample map (.map) of individual IDs and population IDs, no header
- YAML parameter file generated by the scalepopgen CLI

## Outputs

- Filtered PLINK binary (BED) genotype files
- Individual-based summary statistics (counts of heterozygous, homozygous-reference, homozygous-alternative SNPs, transitions, transversions)
- Population-based windowed statistics (average MAF, observed heterozygosity, expected heterozygosity)
- Summary table compiled by the workflow's custom Python scripts

## How to apply

Load a CSV sheet of chromosome-split, tabix-indexed VCFs (or a .p.csv sheet of PLINK BED/BIM/FAM prefixes) plus a two-column .map sample-to-population file, with parameters taken from a YAML file built via the scalepopgen CLI. Apply sample filtering first (e.g. genotype missingness using Plink v1.9, Plink2, and Vcftools v0.1.16), then site filtering (e.g. MAF), because the paper mandates that site filtering follows sample filtering. Optionally prune sites by user-defined Plink2 LD parameters before downstream analyses, then emit the filtered dataset as PLINK binary (BED) files. Compute individual statistics (heterozygous, homozygous-reference, homozygous-alternative SNP counts, transitions, transversions) and windowed population statistics (average MAF, observed and expected heterozygosity), compiled with the workflow's custom Python scripts. Validate that the output is smaller than the input in both samples and sites — in the case study, filtering reduced 442 samples/~25 million SNPs (30 breeds) to 269 samples (17 breeds) and ~23.4 million SNPs, and subsequent LD pruning left 129,357 SNPs.

## Evaluation signals

- Filtered dataset must be smaller than the input in both sample count and site count (case study: 442 samples → 269 samples, ~25 M SNPs → ~23.4 M SNPs)
- Sample filtering must run before site filtering; verify the mandated order in the process logs
- LD pruning, if enabled, should substantially reduce site count (case study: pruned to 129,357 SNPs)
- Summary statistics table must contain the expected per-individual counts (het, hom-ref, hom-alt, transitions, transversions) and windowed per-population MAF/Ho/He values
- Output genotype files must be valid PLINK binary BED/BIM/FAM triplets matching the sample map

## Limitations

- Filtering is two-step and order-mandated: site filtering is carried out after sample filtering; deviating from this order is not supported
- All VCF inputs must be split by chromosome, tabix-indexed, and carry punctuation-free chromosome names
- A sample map file is required, so single-population datasets without population assignments are not directly supported
- Only biallelic SNP data are in scope
