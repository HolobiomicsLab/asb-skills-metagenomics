# unique-coverage-aggregation-across-samples

## Summary

Aggregate unique genome coverage from .sam alignments across all samples in a dataset to create 'artificially deep' shotgun sequencing, so that true microbial positives (high genome cover) can be distinguished from false positives caused by reads mis-mapping to short motifs and transposable elements.

## When to use

Use when shotgun metagenomic alignments (.sam from bowtie2 or SHOGUN) show taxonomic hits against Web of Life reference genomes but per-sample sequencing is too shallow for coverage-based presence calls.

## When NOT to use

- Input is already a feature/abundance table rather than .sam alignments — Woltka can filter feature tables directly, but the aggregated coverage must be computed from alignments
- Alignments were not generated against the Web of Life database — the script currently only works with the WoL database and its metadata.tsv
- You plan to drop genomes directly from an abundance table using calculate_coverages.py output alone — the README states this is not recommended because it decreases apparent read counts rather than redistributing reads via Woltka

## Inputs

- Directory of .sam alignment files (files must end in .sam), generated by bowtie2 or SHOGUN with the bowtie2 alignment option
- Web of Life (WoL) genome metadata file, e.g. databases/WoL/metadata.tsv

## Outputs

- Coverage .tsv with one row per hit genome and columns: gotu, covered_length (bp), total_length (bp), coverage_ratio, strain
- Optionally, filtered .sam files (<input>_filtered.sam) when the coverage .tsv is passed to filter_sam.py with a cutoff

## How to apply

Parse each .sam alignment with calculate_coverages.py, tallying unique genome coverage per reference GOTU so that multiple reads covering the same genomic location count only once — only unique coverage is counted. Sum the covered_length of each target genome across all input .sam files, then compute coverage_ratio = covered_length / total_length, attaching the strain name from the WoL metadata file (databases/WoL/metadata.tsv). The rationale is that datasets often contain many samples from the same environment with similar microbes; aggregating their coverage approximates deep sequencing where true positives have high genome cover while mis-mappings to short common motifs retain low cover. Write the per-genome results (gotu, covered_length, total_length, coverage_ratio, strain) to an output .tsv, which can then drive filter_sam.py thresholding (default cutoff 0.1; the tiny test dataset uses 0.0008).

## Related tools

- **calculate_coverages.py** (Computes the aggregated unique genome coverage (covered_length, total_length, coverage_ratio) of each target genome from all input .sam alignments) — https://github.com/biocore/zebra_filter
- **filter_sam.py** (Consumes the coverage .tsv and filters .sam alignments against the coverage_ratio cutoff, producing <input>_filtered.sam files) — https://github.com/biocore/zebra_filter
- **bowtie2** (Generates the .sam alignments that serve as input for unique-coverage aggregation)
- **Woltka** (Regenerates the abundance (biom) table from the filtered alignments after false-positive hits are removed) — https://github.com/qiyunzhu/woltka

## Examples

```
python calculate_coverages.py -i test_data/ -o test_data/sample_output.tsv -d databases/WoL/metadata.tsv
```

## Evaluation signals

- Output .tsv exists and contains the gotu, covered_length, total_length, coverage_ratio, and strain columns
- Every coverage_ratio value lies within [0, 1], since coverage_ratio = covered_length / total_length
- covered_length never exceeds total_length for any gotu, and identical reads over the same genomic position contribute only once (unique coverage)
- After filter_sam.py, each <input>_filtered.sam contains alignments only to genomes with coverage_ratio at or above the chosen cutoff (e.g. 0.0008 in the test example)
- Retained filtered alignments regenerate a Woltka biom table without error

## Limitations

- Currently only works with the Web of Life database; other reference databases are not supported
- Only unique coverage is counted — multiple reads covering the same genome location do not increase coverage, so very shallow datasets yield extremely low coverage_ratio values requiring a manually chosen tiny cutoff
- Filtering the abundance table directly from calculate_coverages.py output (instead of filtering .sam via filter_sam.py) is not recommended as it decreases apparent read numbers rather than redistributing them in WoLTKA
- Ambiguous reads overlapping multiple reference genomes create artifacts, and this problem grows as the WoL reference database expands
