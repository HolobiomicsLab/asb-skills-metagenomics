# variant-call-coverage-filtering

## Summary

Post-processing filter that discards low-coverage SNP/INDEL calls from ebwt2InDel's .snp output using the tool filter_snp, keeping only events supported by at least m reads (m=5 in the paper, recommended for datasets at >= 25x coverage).

## When to use

Use when you have a .snp file of KisSNP2-format variant calls produced by ebwt2InDel (or ebwt2snp) and need to retain only SNP/INDEL events supported by a minimum number of reads before VCF conversion.

## When NOT to use

- The input is not a .snp call file from ebwt2InDel/ebwt2snp (e.g. it is already a VCF, BAM, or SAM from a mapping-based caller) — filter_snp only understands the KisSNP2 .snp format
- The read dataset has very low coverage (< ~10-25x), where a fixed m=5 threshold would remove true variants rather than only noise
- The goal is depth filtering of reference-mapped alignments rather than coverage filtering of reference-free variant calls

## Inputs

- .snp file of SNP/INDEL calls in KisSNP2 format produced by ebwt2InDel
- integer minimum-coverage threshold m (e.g. 5, recommended for datasets covered at >= 25x)

## Outputs

- filtered .snp file (e.g. output.5.snp) containing only SNP/INDEL events supported by at least m reads

## How to apply

Run filter_snp on the .snp file generated by ebwt2InDel with an integer minimum-coverage threshold m so that only SNP/INDEL events covered by at least m reads are written to the output (e.g. m=5, giving output.5.snp). The rationale is that spurious calls in the positional-clustering output tend to be low-coverage, so coverage is a simple, effective post-hoc quality gate — the paper describes this as discarding low-covered variants 'at post-processing time'. Choose m relative to dataset depth: m=5 is suggested for datasets covered at >= 25x. The filtered file is then ready for downstream reference-based VCF conversion via the snp2vcf pipeline (seqtk -> bwa-mem -> sam2vcf). Validate by checking that the filtered file is a subset of the input and that each retained event has at least m supporting reads.

## Related tools

- **filter_snp** (The filtering tool itself: reads the .snp call file and the threshold m, emits only events covered by >= m reads) — github.com/nicolaprezza/ebwt2InDel
- **ebwt2InDel** (Upstream producer of the .snp call file that this filtering skill consumes) — github.com/nicolaprezza/ebwt2InDel
- **seqtk** (Downstream consumer: converts the filtered .snp file to FASTQ with fake qualities (seq -F 'I') as the first step of the snp2vcf pipeline)
- **sam2vcf** (Downstream consumer: translates SAM mismatches/INDELs from bwa-mem alignments of the filtered calls into VCF entries)

## Examples

```
filter_snp output.snp 5 > output.5.snp
```

## Evaluation signals

- Output file (e.g. output.5.snp) exists and contains a subset of the events in the input .snp file (line count <= input line count)
- Every retained SNP/INDEL event in the output is supported by at least m (e.g. 5) reads, per the filter's definition
- Running with m=0 or omitting the threshold should reproduce (approximately) the unfiltered input
- Downstream conversion (seqtk -> bwa-mem -> sam2vcf) yields a valid VCF whose entries correspond to events present in the filtered calls.snp
- Retained variant count scales sensibly with coverage: at >= 25x depth with m=5, the majority of true variants should survive the filter

## Limitations

- The threshold is purely coverage-based with no per-call quality score; the paper recommends m=5 specifically for datasets covered at >= 25x, and the appropriate m must be re-tuned for other depths
- filtering is applied only at post-processing time — the main ebwt2InDel algorithm itself does not suppress low-coverage clusters, so recall/precision of the raw .snp file is unaffected upstream
- Duplicates arising from analyzing a dataset and its reverse-complement are not handled by filter_snp; separate de-duplication of the final VCF is required
