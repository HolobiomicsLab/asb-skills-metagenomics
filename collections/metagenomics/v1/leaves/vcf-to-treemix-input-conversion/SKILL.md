# vcf-to-treemix-input-conversion

## Summary

Converts filtered biallelic SNP VCF genotype data into TreeMix-compatible input and runs the TreeMix phylogeny sub-workflow of scalepopgen, including bootstrapping, migration-edge estimation, and consensus tree construction.

## When to use

Use when inferring population trees and migration events from filtered biallelic SNP genotype data (VCF or PLINK binary) that must be transformed into TreeMix-compatible input, especially when bootstrapping and optimal migration-edge selection are needed.

## When NOT to use

- The analysis goal is admixture proportions or PCA rather than a population tree with migration edges (use the explore-genetic-structure sub-workflow with ADMIXTURE/PCA instead)
- The genotype data are multi-allelic or not filtered (sample/site filtering, and recommended LD pruning, should precede TreeMix input conversion)
- Only pairwise population differentiation statistics are needed and no phylogenetic tree is required

## Inputs

- Filtered biallelic SNP VCF file(s), chromosome-split and tabix-indexed
- PLINK binary files (bed/bim/fam) as alternative genotype input
- Sample map file (.map) with two tab-delimited columns: individual IDs and population IDs, no header
- YAML parameters file specifying TreeMix bootstrapping and migration-edge options

## Outputs

- TreeMix-compatible input file produced by the in-house Python conversion script
- TreeMix population tree figures with inferred migration edges (plotted via bundled R scripts)
- OptM summary identifying the discrete optimal number of migration edges (Δm)
- Consensus tree from bootstrap replicates (PHYLIP CONSENSE) plotted with ete3

## How to apply

First filter the VCF (sample filtering, then site filtering such as missingness and MAF, with optional Plink2 LD pruning) and supply a tab-delimited sample map of individual-to-population IDs. Transform the filtered VCF with the in-house Python conversion script, configuring bootstrapping and user-defined migration edges via the YAML parameters file generated by the scalepopgen CLI. Run TreeMix (v1.13) with bootstrapping and migration edges to infer population trees and estimate pairwise migration events, then summarize runs with OptM (v0.1.6), which selects the optimal number of migration edges via the second-order rate of change in likelihood (Δm). Collapse bootstrap replicate trees into consensus trees using PHYLIP (v3.697) CONSENSE, and plot TreeMix trees with the bundled R scripts and consensus trees with ete3 (v3.1.3).

## Evaluation signals

- The consensus tree figure is produced (validation check stated in the article)
- The OptM summary identifies a discrete optimal number of migration edges for the population tree
- TreeMix-compatible input was generated from a filtered, LD-pruned biallelic SNP VCF (e.g. the study reduced ∼25M SNPs in 442 samples to 269 samples / ∼23.4M SNPs, then 129,357 SNPs after LD pruning)
- Bootstrap replicate trees exist and CONSENSE successfully collapses them into a single consensus tree
- The YAML parameters file from the scalepopgen CLI passes format checks for the treemix sub-workflow options

## Limitations

- VCF inputs must be split by chromosome and tabix-indexed, and chromosome names must not contain punctuation marks
- LD-based filtering is recommended before the analysis; unfiltered genome-wide data (e.g. ∼25 million SNPs) is impractical
- The pipeline requires Nextflow, Java, and a container/environment system (conda/mamba/singularity/docker) — only these three dependencies are installed by the user
- The optimal number of migration edges may be ambiguous; validation requires that OptM identifies a discrete optimum
