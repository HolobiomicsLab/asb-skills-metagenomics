# yaml-configuration-of-genomic-workflows

## Summary

Configure the scalepopgen Nextflow population-genomics pipeline by generating a YAML parameter file that selects options for its four sub-workflows (filtering/basic statistics, genetic structure, TreeMix phylogeny, signatures of selection), using the scalepopgen CLI and running with a container profile such as conda, mamba, singularity or docker.

## When to use

Use when a Nextflow population-genomic analysis on biallelic SNP data (VCF or PLINK binary input) requires a validated YAML params file specifying which sub-workflows and tool options to run, or when launching scalepopgen with test/test_full profiles.

## When NOT to use

- Your data are not biallelic SNP genotypes in VCF or PLINK binary format — scalepopgen is explicitly scoped to those inputs
- You only need to run a single standalone tool (e.g. plain PLINK or TreeMix) without sub-workflow orchestration — direct execution is simpler than building a YAML params file
- You need Nextflow-level configuration (resources, executors) rather than analysis parameters — use custom config files, since they must not supply parameters for this pipeline

## Inputs

- YAML parameters file (path passed via -params-file) generated by the scalepopgen CLI
- comma-separated input sheet for VCF files (.csv with header chrom,vcf,vcf_idx; chromosome-split, tabix-indexed VCFs)
- comma-separated input sheet for PLINK binaries (.p.csv with header prefix,bed,bim,fam)
- tab-delimited two-column sample map (.map: individual IDs, population IDs, no header)
- profile selection (docker/singularity/conda/mamba) and optional test or test_full profile

## Outputs

- Configured Nextflow run of scalepopgen executing the four sub-workflows
- citation_ folder of relevant references in biblatex format generated by the CLI
- pipeline results collected and visualized by the bundled Python/R scripts

## How to apply

Install Nextflow, Java, and one container/environment system (the README recommends mamba), then clone scalepop48/scalepopgen. Rather than hand-writing the many tool parameters, use the scalepopgen CLI (cloned from scalepopgen-cli, installed via pip3 install --no-cache-dir -r requirements.txt) to navigate each sub-workflow's options, validate input formats, save the selections as a YAML file, and — as a side effect — generate a citation_ folder of biblatex references that must be cited in any resulting manuscript. Point Nextflow at the YAML via -params-file together with a -profile (docker/singularity/conda/mamba) and cap concurrency with -qs. Validate the setup first with the small bundled dataset using -profile test before real data, or reproduce the paper's cattle WGS results (442 samples, 30 breeds) with -profile test_full.

## Examples

```
nextflow run scalepopgen/ -profile test,singularity -qs 10
```

## Evaluation signals

- The CLI completes without format errors and writes a YAML file plus a citation_ folder containing biblatex references
- A Nextflow dry run with -profile test on the bundled small dataset completes successfully before running real data
- The YAML keys match the sub-workflow options the CLI exposed (filtering/basic statistics, genetic structure, phylogeny, signatures of selection)
- nextflow run accepts the file via -params-file without configuration errors, and custom -c config files are not used to supply parameters
- The selected -profile (docker/singularity/conda/mamba) resolves and the pipeline executes on Linux locally or on an HPC cluster

## Limitations

- Parameters may only be provided via the -params-file YAML; custom Nextflow config files (including -c) cannot be used to supply them
- VCF inputs must be split by chromosome and tabix-indexed, listed in a .csv sheet whose header is exactly 'chrom,vcf,vcf_idx', and chromosome names must contain no punctuation marks
- Three dependencies must be pre-installed by the user (Nextflow, Java, and conda/mamba/singularity/docker); Nextflow downloads all remaining tools automatically
- The pipeline is Linux-only and limited to biallelic SNP data
